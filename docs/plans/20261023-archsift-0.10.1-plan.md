## NX01: complete Web delivery through the CLI tool package

### Packaging choice

Choose **a complete framework-dependent Web publish closure embedded in `ArchSift.Cli.nupkg`**. Keep it separate from CLI assemblies under `tools/net10.0/any/web/`: `ArchSift.Web.dll`, `.deps.json`, `.runtimeconfig.json`, application dependencies, `wwwroot/` static assets, required resource/schema content and notices. Include Web's Setup/Testing/TestGate dependencies according to the actual publish closure. Do not copy only the DLL, flatten two applications' descriptors, or place a self-contained win-x64 runtime inside the portable tool package.

This retains the tool identity and adjacent `web/` layout. An independently installed companion package adds a second version/resolution lifecycle and is rejected for this patch. Keep self-contained Windows ZIP/Setup for the no-SDK runtime channel. NuGet installation needs the approved SDK; Web execution needs compatible Core and ASP.NET shared runtimes, qualified at 10.0.13. Diagnose missing ASP.NET clearly. CLI-only commands must retain their Core-only runtime prerequisite, without acquiring an ASP.NET startup dependency.

Build Web for the candidate identity into fresh external staging using explicit offline sources, matching Release/TFM/version properties, framework-dependent publish and no apphost for the embedded payload. Validate and explicitly include that closure in tool pack. Order build/publish/stage/pack so `pack --no-build` cannot ship stale Web output. CLI-only development builds may remain possible; a distributable pack must fail when the matching complete payload is absent. Add build/pack orchestration without a CLI/Web build cycle or Core-to-host dependency. Check RID-specific transitive assets; if closure is not portable, stop and revise the design instead of claiming unsupported platforms.

Generate a version/source-bound inventory of safe relative paths, sizes and SHA-256 values. Verify containment, duplicates, required files, matching product assemblies and enumerated bytes before Web starts. Missing, altered, extra executable/dependency or mixed-version payloads fail clearly. Packaged Release execution must not search a development checkout or another installed Web directory. A local manifest detects corruption but is not its own authenticity anchor: bind it and the complete nupkg hash to independently reviewed approvals and release manifests. Never package user configs, tokens, private targets/reports or machine paths.

### Standalone Launcher bootstrap

Inspection found two additional constraints: `ProfileStore` always loads Setup `install.json`; Launcher starts `versions/<selected>/web/ArchSift.Web.exe`. A DLL-only payload cannot provide an independent Launcher. Resolve both in NX01, retaining direct UI and Launcher acceptance.

| Entry/context | Planned behavior |
| --- | --- |
| `archsift ui --config <existing-json>` | Verified adjacent Web; explicit dotnet host for framework-dependent payload; existing config/external writable state |
| Existing `archsift launch --root <managed-install-root>` | Existing Setup ownership, verified selected version, protection, lease, receipts and managed profiles |
| New opt-in `archsift launch --root <external-state-root> --config <existing-json>` | Bootstrap portable Launcher state/catalog referencing the explicit external config, without Setup/ZIP/source checkout |
| Later portable `launch --root` | Recognized portable root only; invoking tool supplies matching verified Web; validate selected config |

Use a separately identified portable marker, proposed `workbench-state.json` schema 1, plus external profile catalog/selection. Do not counterfeit Setup `install.json`, claim Setup protection for external profiles, copy the cache into a managed installation, or persist cache paths as executable ownership. Keep user state outside immutable tool/cache/source roots. Show mode and actual version. For managed mode, require Launcher/tool and verified selected child identities to agree; diagnose mismatch and direct use of the selected installation's entry instead of silently combining versions. Never turn an invalid managed root into portable mode.

Bootstrap is explicit, bounded and transactional. Require valid config and canonical disjoint state/target/library/output/package roots; reject reparse/path escapes, unknown nonempty roots, ambiguous markers, busy roots and unsupported schemas. Validate before writing, stage/commit only owned marker/catalog/selection files, recover interrupted creation, and preserve existing files on error. Plain `launch --root <unknown-root>` explains the initialization command without inventing target/config defaults. Add context-specific locks and optimistic hash checks. Managed schemas/receipts remain unchanged; new portable metadata is additive and is not passed to 0.10.0 as managed state.

Place the host-context/resolver boundary in CLI/Web/hosting, keeping Core/analysis Contracts free of installation/profile policy. Select native or dotnet child correctly. Preserve loopback token/parent protocol, dirty/running-job shutdown checks, readiness, concurrent UTF-8 stdout/stderr forwarding, cancellation, parent-death cleanup and no-orphan behavior. Cover Git for Windows identity while stdin carries parent lifetime: carry forward child-only `GIT_REDIRECT_STDIN=off` or a demonstrated equivalent at the Git subprocess boundary. Do not change caller/persisted environment or silently replace the existing IFX wrappers/helper.

## NX02: compact, accessible JSON inventory

Change `renderInventory` in `src/ArchSift.Web/wwwroot/test-workbench.js`, existing stylesheet/localization assets and focused browser checks. The separate Results disclosures and executable rule/report contracts keep their current behavior.

- Use native `details`/`summary` per JSON ruleset, **collapsed initially** for a newly selected configuration. Show filename, displayed canonical source path and enabled case count while collapsed; keep aggregate ruleset/JSON/C# counts visible. Collapsed must not mean disabled/excluded.
- Keep copy-to-external-library/open-editor as a labelled button outside interactive `summary`, visible while collapsed. Toggling must not copy/edit; editing must not toggle. Retain existing server operations, source-read-only and saved-byte/run semantics.
- Add **Expand all / Collapse all** for JSON inventory only, with accessible labels and announced state/count. Disable for no rules; explicitly show no-enabled-case states. Preserve errors; failed retrieval must not look like a successful empty inventory.
- Use native Enter/Space/Tab semantics, visible focus, screen-reader summaries and normal flow; wrap long paths/IDs. Do not nest buttons in summary or add conflicting ARIA. New labels work in existing English/Chinese UI locales; formal docs remain English.
- Keep state **in memory for the current Web session**, keyed by canonical config identity and canonical ruleset path, never translated labels/index/order. Refresh/locale rerender preserves known states; new rules start collapsed; removed rules are discarded; config switches clear state. No browser storage/server config writes. Content/count changes at the same path remain visible.
- Restore focus by logical rule/action identity during rerender. Bulk controls retain focus; if focused content is hidden, focus its summary. Copy/edit preserves valid disclosure state and existing editor navigation, with predictable return focus.
- Expanding exposes every original case ID in original order and all paths. No execution filtering, virtualization, lazy loading or selection semantics. Run/cancel/history, C# summaries, responsibility/deferred surfaces and audit semantics remain independent of disclosure state.

The accepted IFX-size fixture has **13 JSON ruleset files / 401 enabled JSON cases**, plus **92 C#**, totaling **493**. Check closed/partial/open views, normal/narrow viewport, both locales and keyboard-only navigation. Compare serialized inventories and execution requests: disclosure state never becomes selection authority. For NX02, compare exact outputs with identical candidate inputs and controlled volatile fields. Across 0.10.0/0.10.1, enumerate legitimate product/source/time/run-ID differences explicitly, requiring exact policy/rule bytes, typed identities and substantive outcomes. Do not claim cross-version raw byte equality by masking arbitrary differences.
