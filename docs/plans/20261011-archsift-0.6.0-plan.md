## 3. Chain execution and progress

### 3.1 Options and identity

Add CLI chain verify --max-concurrency <1..4> and optional Web maxConcurrency; default 1. Reject duplicate/noninteger/out-of-range/unknown input as configuration error, no coercion.

Concurrency is execution metadata, not ruleset/chain/config schema or policy identity. Snapshot/summary record actual options. Freeze new report compatibility in A; never silently add fields to old additionalProperties: false schemas. Old reports use old schemas; JSON remains authority.

One job spans submission/preparation/evaluation/writing. Discover/freeze/build once. Saved library bytes captured at submission govern execution despite later save/delete.

### 3.2 Stages and entry states

Stable phases: preparing, acquiring-evidence, evaluating, writing-reports, finished. Skip unnecessary evidence phase. Parallel evaluation/writing may overlap; entry states express actual progress rather than pretending simultaneous stages.

Entry waiting→running→writing→completed/partial/failed/skipped/cancelled. Compliance separately compliant/noncompliant/inconclusive/not-applicable; violation is not execution failure. Downloads become available only after successful writes; failed writes show current diagnostics.

Atomic progress: job/run IDs, monotonic revision, phase, total/ended/executed/skipped/running counts, ordered entryIds/states/compliance/start-end/diagnostics/output availability. Skipped never verified; no inconsistent snapshots or UI-invented timestamps.

Poll shared API for stage/duration/states/counts, no invented exact percentages. Poll/network failures show unavailable current state, not old completion. Shared CLI/Web events; progress stderr never contaminates machine stdout.

### 3.3 Scheduling, cancellation and drift

- Serial 1 preserves order; bounded 2–4 dispatch in definition order, active entries including Worker/writes never exceed bound. Verify actual concurrency for synchronous declaration checks, not Task.WhenAll appearance. Shared build once; isolated Workers.
- Exclusive entry result/output containers, aggregate original indexes; coordinator owns global cancellation/drift without unlocked shared mutable lists. Findings/exceptions/ruleIds isolated by entryId.
- Invalid/missing entry or failure records diagnostics while independent entries continue. Shared-evidence failure makes affected rules inconclusive, declarations may continue. Keep exit/compliance precedence.
- Cancellation stops dispatch, propagates to in-flight tasks/Workers, waits for owned exit/audits. Unstarted skipped with reason, completed reports retained, overall cancelled/130. Preparation/hash checks cancellable.
- Drift stops dispatch/cancels affected work, never impersonates user cancellation. Revoke affected current-source binding/compliance; retain global-input-drift/partial 4. Unstarted skipped; prior completed results identify frozen inputs; valid violations retain precedence.
- Preserve before/after source/build verification. Reducing checks requires proof of equivalent drift boundaries; performance never authorizes weakening. Recheck before final summary for late drift.
- Snapshot/reports/diagnostics/summary use fresh run directories. End job only after tasks converge and summary saves. Persistence failure failed/error, no stale success; all formats agree.

### 3.4 History display

Refresh restores actual progress from same-service API without replacing current job through history selection. Restart never resumes automatically or treats old reports as active. Old final reports retain versions; snapshot without trustworthy summary is incomplete. Persistent queues/restart execution/new history scanning excluded.

## 4. Launcher and config storage

### 4.1 Paths and selection

configRoot=<canonical installRoot>/config; profiles.json catalog, selection.json recent selection, default.json new managed config. Reserved metadata names are not run configs. No alternate AppData/registry/environment/target writes.

Independent schemaVersion 1 catalog: stable profileId/name/canonical absolute configPath/defaultProfileId. Selection schemaVersion 1 only selectedProfileId. No tokens/URLs/PIDs/results/selected binary version. Compute protection against actual install, never persist self-declared protection.

Reject duplicate canonical paths; same-name/equal-hash distinct paths remain separate. Apply Windows case rules, reject reparse/escaped writes. Atomic hash-checked metadata prevents concurrent overwrite. Unknown schema/duplicates/corruption/conflicts preserve bytes and require review, no reset. Registration reads external files without copy/repair/adoption.

Always show selection before Workbench, no automatic analysis. Preselect valid recent/default, display full path/protection and await click. Missing/invalid choice stays visible, no silent fallback. Unregistered default.json not adopted; expose conflicts. Save recent selection only after explicit successful start.

### 4.2 One managed config and protection

Protection requires exact unique install.json.ConfigPath inside configRoot and valid install/config/library contracts. Being inside config is necessary but insufficient; other internal/external JSON remains unmanaged without backup/rollback promises.

Catalog/selection do not expand Setup state. Compatible upgrade/rollback preserves bytes and recent selection rather than binary-era restoration, excludes receipt state hashes; selection edits do not count as managed-config edits. No automatic metadata recovery promise; distinguish retention from backups.

Managed library still fully backed up. External profiles sharing it show per-resource config-unmanaged/library-managed labels. Verify locks/path relationships; one Workbench per launcher. Reports retained, not copied on upgrade.

Explicit file selection registers profiles. New config only reviewed target/path/JSON into free configRoot path, no overwrite/managed replacement. Missing managed config is not repaired by creating another file; explicit Setup recovery, never launcher install.json edits. No multi-managed/adopt-any-config feature.

### 4.3 Validation and ownership

New archsift.exe launch --root <installRoot>, existing ui --config retained. Local loopback launcher independent of config, no new desktop/install framework. Host decomposition is implementation choice; owning parent stays alive.

Separate install/binary integrity from profile health: broken managed JSON cannot hide selection page, untrusted binary blocks launch with reason. Validate size/schema/version/relative paths from config directory/target-entry/output-library/protected boundaries/links/network settings. No discovery/build/restore/rule evaluation/application entry or automatic schema upgrade.

List name/full path/target-entry/TFM-config/output-library/health/per-resource protection. Workbench shows profile name/path/running version and frozen job target.

Recheck selected JSON/install at launch to close drift window. Explicit-array verified child, owned tree, private local browser/reopen/shutdown. URL/token only memory/private channel, never logs/catalog/selection/shortcuts/receipt. Existing explicit CLI visible-URL contract remains; launcher must not persist it.

Switch resolves tasks (wait/cancel) and unsaved edits (save/explicit discard), closes old owned service/listener before new profile. Tab close is not service exit. Preserve 0.5.0 shutdown/Ctrl+C/parent/timeout/exact-tree boundaries. No silent second launch; fresh token/cache/results per session.
