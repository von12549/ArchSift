## 2. 0.5.0 实现基线与改动依赖

- `ToolIdentity.Version` 已提供当前程序版本，直接复用其身份；不可从安装目录或策略版本推断。
- `ChainService.Prepare` 已冻结项目快照和可用 ruleset 字节；`RunAsync` 共享一次必要的构建／程序集证据，隔离每条目输出，串行验证。保留这些基础，不将每个条目改成一次独立发现／构建。
- Web 当前在创建 job 前同步执行 `Prepare`，准备阶段既不可轮询也缺乏 job 取消入口。真实进度要求先建立 job，再进行可取消的准备工作；CLI 也走同一 Core 阶段和汇总逻辑。
- Web 当前限制一个活动 job，history 最多保留 20 个内存任务。0.6.0 只增加一个 chain 内的并发，不开放多个工作台 job 同时执行。
- Setup `Installation`、plan、receipt、journal 和状态捕获只包含一个 `ConfigPath` 及其规则库。保留单配置模型；日常 profile 选择不改 `install.json`。
- 当前 0.5.0 Setup 明确拒绝未知的 0.6 版本族；必须由新 Setup 声明并验收兼容关系，不能假定旧 Setup 自动接收新包。

实现期间新增进度及启动器 DTO 属于 Contracts／宿主边界。Core 不依赖启动器 profile 清单、Setup 状态或 Web；Core 只接收解析后的运行配置、冻结输入和执行选项。

## 3. Chain 执行与进度契约

### 3.1 参数和身份

CLI `chain verify` 增加 `--max-concurrency <1..4>`；Web chain 请求增加可选 `maxConcurrency`；省略均为 1。重复 CLI 选项、非整数、越界及未知字段按配置错误拒绝，不截断或静默改值。

并发度是本次执行选项，不加入 ruleset、chain 定义或 RunConfiguration schema，不改变策略身份。最终 chain 快照／summary 记录实际选项，使执行可审计。新增报告字段和兼容读取规则在 0.6-A 冻结；不悄悄向 `additionalProperties:false` 的旧 schema 填字段。旧报告仍按其旧 schema 读取；新报告保持 JSON 为权威，HTML/SARIF 为投影。

运行身份从提交后开始，准备、验证、写出均属于同一个 job。项目发现、规则字节捕获和构建证据只准备一次。规则库在提交时捕获的已保存字节是执行依据；之后保存或删除规则不替换当前任务的冻结政策。

### 3.2 阶段与条目状态

机器阶段使用稳定英文标识：`preparing`（项目发现、规则／输入冻结）、`acquiring-evidence`（必要构建／已有产物核验）、`evaluating`、`writing-reports`、`finished`。无构建／程序集需求时直接略过证据阶段；不展示不存在的步骤。并行下条目执行与写出可能重叠，以条目状态表达，不能假装所有条目同时进入同一阶段。

条目生命周期为 `waiting` → `running` → `writing` → 终态；终态沿用 `completed/partial/failed/skipped/cancelled`。`compliance` 独立使用 `compliant/noncompliant/inconclusive/not-applicable`；违规不是执行失败。条目输出成功写出后才标成可下载的终态；写出失败有当前诊断，不显示成功链接。

进度快照包含 job/run 身份、单调递增 revision、阶段、总条目数、已结束／已执行完／跳过／运行条目数，以及按 chain 顺序排列的 entryId、执行状态、合规性、开始／结束时间、当前诊断和输出可用性。不得把跳过算成已验证。快照原子发布，前端不能读到不一致的状态／计数；报告时间不能由 UI 估算。

UI 复用轮询 API，显示阶段、耗时、条目状态和明确计数，不承诺精确耗时百分比。网络／轮询失败显示当前不可读取，不据旧数据宣称完成。CLI 进度与 Web 共用事件源；机器结果 stdout 保持原约定，进度输出到 stderr，不污染 JSON。

### 3.3 调度、取消与输入漂移

- 并发度 1 保持现有顺序；2–4 使用有界调度，按定义顺序派发，活跃条目（含其 Worker 和写出）不超过所选值。声明规则主要同步执行，必须验证实际并发，不能用 `Task.WhenAll` 外观当证据。共享构建不并行复制，Worker 仍为隔离子进程。
- 每个条目独占结果容器和输出目录，汇总按原始索引收集；全局取消／漂移由协调器统一决定，不共享无锁可变 List/Dictionary。findings、例外和 ruleId 仍按 entryId 隔离。
- 缺失／无效规则或单条目执行失败产生诊断，其余独立条目继续；共享证据失败保持受影响规则无法判定，声明规则可继续。保留既有执行、合规、退出码汇总优先级。
- 用户取消停止派发，向全部在途任务／Worker 传播取消，等待受拥有进程退出和审计写出；未启动条目标为 skipped 并注明取消。已落盘且完成的条目保留，整体 `cancelled/130`。准备和哈希复核也必须响应取消。
- 输入漂移停止新派发并取消在途验证。漂移是原因，不伪装成用户取消；受影响在途结果必须撤销当前源码合规／绑定，整体保留 `global-input-drift` 和 `partial/4`。未启动条目 skipped；漂移前已确认完成的结果仍标明其冻结输入，既有有效违规的汇总优先级保留。
- 保留源／构建证据前后复核语义。任何减少复核次数的优化必须先证明等价的漂移检测边界；性能不足不授权削弱检测。最终汇总前再核对输入，防止最后一条目之后的漂移被漏记。
- snapshot、子报告／诊断和 summary 只能写入本次新目录；全部派发任务收敛且 summary 成功写出后 job 才终结。落盘故障明确 failed/error，不能展示旧成功。JSON/HTML/SARIF 的输出顺序和事实一致。

### 3.4 历史恢复显示

同一服务内刷新页面可从 job API 恢复当前真实进度，历史选择不替换当前 job。服务重启后不自动续跑，不把旧报告当活动任务；旧最终报告按原版本展示，存在 snapshot 但没有可信最终 summary 的目录不得显示已完成。持久任务队列、跨重启自动恢复执行和新增历史扫描功能均不在范围内。

## 4. 启动器与 config 存储契约

### 4.1 路径、身份与默认选择

固定 `configRoot = <规范化 installRoot>/config`。清单为 `config/profiles.json`，最近选择为 `config/selection.json`，受管新配置为 `config/default.json`。三个名称保留，不把前两份元数据当运行配置。不得写入安装目录以外的 AppData、注册表、环境变量或目标仓库作为这些记录的替代。

清单采用独立 `schemaVersion:1`，每项保存稳定 `profileId`、显示名和规范化绝对 `configPath`；默认引用保存 `defaultProfileId`。选择记录采用独立 `schemaVersion:1`，只保存 `selectedProfileId`。不保存 token、会话 URL、PID、合规结果或安装选中版本。条目上不持久保存可伪造的“受保护”结论，运行时与安装状态核对。

同一规范化路径不得重复登记；不同完整路径即使同名或 hash 相同也保留独立条目。Windows 路径身份按其大小写规则处理，拒绝 links/reparse 和越界写入。清单／选择原子写出，检查既有 hash，拒绝并发覆盖；未知 schema、重复 key、损坏或冲突保留原文件并提示审阅，不自动重置。登记只读取外部文件，不复制、修复或接管它。

每次打开启动器都先呈现选择页，不自动启动分析或工作台。无历史选择时预选登记的 default；有合法最近选择时预选该项，仍展示完整路径和保护标签并等待用户点击启动。无效／缺失选择保持可见，不自动跳到另一份 JSON。未登记的同名 `default.json` 不自动接管；有冲突先显示冲突。显式选择并成功启动后才保存最近选择。

### 4.2 一份受管配置与保护边界

保护需同时满足：配置是 `install.json.ConfigPath` 明确登记的唯一文件，且位于 `configRoot` 下，安装与配置／库契约通过校验。位于 config 目录是必要条件，不是自动受管条件。目录内其余 JSON 与目录外 profile 均为外部未受管配置，不获得其配置文件的 Setup 升级备份／回退承诺。

profiles/selection 是启动器元数据，不扩大 Setup 的单 ConfigPath 状态集合。兼容升级／回退保留这些文件的现有字节，不跟随二进制回退恢复最近选择，不加入既有 receipt 状态哈希；选择变化不能使兼容回退变成“用户修改受管配置”。其自动备份恢复不在本版承诺内，UI／文档应明确区分元数据保留和受管状态备份。

受管规则库仍按原契约完整备份。外部 profile 引用同一受管库时，标签逐资源说明“配置未受管／此规则库属于受管状态”；不能据此宣称外部配置受保护，也不能宣称库完全未保护。共享库的锁和源目标路径关系必须校验，同一启动器一次只运行一个工作台。reports 仍仅保留，不纳入升级复制。

新 profile 可来自显式文件选择；新建配置只允许在 configRoot 内经用户审阅目标／路径／JSON 后写入空闲路径，不默认覆盖已有文件或替换受管路径。已有受管配置缺失时新建另一份文件并不自动修复安装状态；安装保护恢复须走明确审阅的 Setup 流程，不由启动器改 install.json。本版不新增多受管配置／任意配置接管功能。

### 4.3 启动前校验与进程所有权

新入口为 `archsift.exe launch --root <installRoot>`；显式 `ui --config <JSON>` 保持可用。启动器采用本地 loopback 引导页，无新增桌面 GUI 框架或独立安装技术要求；独立于目标 JSON 启动。宿主项目拆分是实施选择，但拥有 UI 子进程的启动器父进程必须始终存活。

启动器分别检查安装／选中二进制完整性及每份 profile 健康。受管 JSON 损坏不能使选择页消失；安装二进制不可信则禁止启动，允许查看原因。校验包括大小／JSON schema、所选版本支持、相对路径按 JSON 所在目录解析、目标／入口、输出／库与安装受保护目录边界、links/reparse、显式网络设置。只校验，不 discovery、build、restore、规则验证或目标应用执行；不得给“不兼容”状态自动升级 schema。

列表展示名称、完整 configPath、目标／入口、TFM／配置、输出／库、有效／缺失／无效／不兼容状态和逐资源保护标签。工作台始终展示本次 profile 名称、完整路径和当前运行产品版本，运行目标仍显示 job 冻结上下文。

启动时再核对所选 JSON／安装身份，避免校验后文件变化。启动器以参数数组启动已验证的选中程序并拥有进程树；就绪后自动打开本地私有地址，提供重新打开页面和安全关闭入口。URL/token 只在内存和私有通道流转，不写 stdout/stderr 日志、清单、选择记录、快捷方式或 receipt。原显式 CLI 展示启动 URL 的交互契约保留，启动器不得把该输出转存日志。

切换先处理当前任务（等待或用户取消）与未保存配置／编辑器修改（保存或明确放弃）；关闭旧服务并确认 owned process／监听退出，再启动新 profile。关闭浏览器标签不等于退出服务；安全关闭、Ctrl+C、父退出、超时和强制 owned-tree 清理沿用 0.5.0 生命周期边界。未退出不能悄悄再启动。新会话使用新 token，旧 job、编辑器、库缓存和结果不得带入。

## 5. Setup、旧安装与升级／回退

- 保留 Setup schemaVersion 1 的单 ConfigPath／LibraryPath 模型，不新增 profiles 数组或将选择记录塞进 install.json。独立启动器元数据可由新程序读取，不要求旧二进制理解它。
- 新安装默认路径变为 config/default.json；这是新安装路径约定的变化，不是现有用户配置的自动改名。后续实现须同步新 Setup 的计划校验、smoke、包内指南和合成用例。
- 0.5.0 既有配置在 configRoot 内时，升级保留其实际路径（例如 project.json 或 ifx.json）、字节、库身份及全部旧 receipt；启动器初始化明确列出它作为既有受管默认项。`default.json` 是新安装默认文件名，不能靠复制或重命名制造第二份受管文件。
- 既有 ConfigPath 在 configRoot 外的旧接管安装：只读展示其旧契约事实与 0.6.0 保护边界，不自动移动、取消所有权或重写历史 receipt。该布局的 0.6.0 受管升级计划拒绝，要求单独审阅重定位／新安装后再继续；自动迁移和现场重定位不在本版实现范围。显式 ui --config 仍可按原安全契约使用，不能宣称获得新保护。
- 新 Setup 必须验证 0.5→0.6 兼容升级及由新 Setup 执行 0.6→保留的 0.5 回退；旧 0.5 Setup 不承诺处理 0.6 包。config/library/chain policy schema 均保持 1，无未知 schema 迁移。旧最终报告保持按旧契约读取；新增 chain 报告版本不能改变保存的 policy schema。
- 缺失／损坏／不兼容的唯一受管配置或受管库阻止 upgrade/apply/rollback 按当前状态宣称通过；inspect 分别返回安装身份和状态错误，避免笼统 verified。无效外部项只影响其启动，不单独阻止受管二进制升级；若其引用受管库，则该库仍参与受管状态核对。
- 升级时所有该安装拥有的启动器／工作台进程需退出，Setup 独占锁及 library 锁继续生效。选择页也算活动宿主，不能在仍运行时替换其版本。保留原有 stale plan、后续受管修改拒绝回退、并存旧版本和中断恢复要求。
- 清单与选择文件的首次初始化是新启动器显式元数据写入，不由安装 smoke 隐式初始化；不改变旧版本不可变 payload。兼容回退保持外部文件／启动器元数据不动，不以回退之名扫描或恢复 config 目录所有 JSON。

## 6. 测量与性能门禁

历史只读参考：同一输入和四组规则 hash 的两份 0.5.0 IFX chain summary 为 1,257ms 和 1,209ms，四子分析分别为 82/83/74/86ms、88/81/72/68ms；105 项目、585 输入记录、声明层 182 规则、existing/net10.0/Debug、无程序集 Worker。路径分别为 `D:/IFX-10-Root/ArchSift/reports/607d2f2f9ea9492abb8c9d1b1ca29ccf/chain-summary.json` 与 `.../732d83bdf6404248912bb8835f2dcb84/chain-summary.json`。这些旧报告不是当前源验收，也不是并行收益证据；旧计时遗漏 Prepare 和最终 summary 写出，子计时不含后续投影写出。
