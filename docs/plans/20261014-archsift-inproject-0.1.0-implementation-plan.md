## IP00-A–E 契约与安全边界

这些阶段落实已确认的产品范围，不重新打开产品决议。每阶段形成版本化设计记录和对应契约样例；仅写出标题或待办清单不能标为完成。不能满足已确认能力时记录具体阻碍、影响和候选方案；范围变化返回用户决议。

### IP00-A 组件、身份与兼容方案

- **交付物**：InProject 宿主、薄 xUnit 项目、桥接组件与既有 Core／Contracts／ArchUnitNET Worker 的依赖图；产品名、版本、包名、标签及共享组件身份规则；固定 xUnit、运行器、测试项目 TFM、目标 SDK／targeting pack 前提，以及与 .NET 10 Worker 的进程协议和错误映射。Core 不引用宿主或 xUnit，net8/net9 业务项目不被迫升级到 net10。
- **验收场景**：用 net8/net9/net10 的兼容性矩阵核对测试发现、桥接调用和 Worker 边界；不同产品宿主调用共享规则语义；不兼容 TFM、缺少 SDK／运行器和协议版本不符都有确定状态，不把零执行记为通过。
- **进入下一阶段**：依赖方向、版本身份与跨进程协议字段冻结；未验证的组合明确列为阻碍，不能默认受支持。

### IP00-B 配置、输入身份与 owned 路径

- **交付物**：`project.json`、规则集合引用、本机覆盖值、`version.lock.json`、载荷 manifest 的 schema／示例和路径基准；业务输入、工具配置、规则、测试桥接与运行产物各自的身份和失效规则；`.archsift/` 内可写子目录及可选每 worktree 外置证据根的所有权契约。逐调用点列出既有 `EnsureDisjoint` 的 ArchSift 原模式与 InProject 新模式，不能整体放宽原检查。
- **验收场景**：任意启动目录解析同一配置；多个 solution 候选拒绝猜测；配置／规则／锁变化使旧门禁失效；自身目录排除但显式业务引用时报范围冲突；链接、`..`、大小写碰撞、外置路径和跨 worktree 写入拒绝；嵌套快照不递归复制，也不意外继承祖先 MSBuild 输入。
- **进入下一阶段**：每类写入有唯一 owner、规范绝对路径与允许根，工具资产虽被业务扫描排除仍可独立绑定。

### IP00-C 构建支持矩阵与日常关联

- **交付物**：单 solution `.sln`／`.slnx`、项目／引用闭包、Configuration、逐项目 TFM、条件／表达式、生成输入及外部依赖的支持矩阵；每次新快照、离线恢复、禁止隐式恢复和实际编译取证协议。关联记录包含响应文件、编译输入／参数、imports、SDK／任务／生成器、必要环境摘要、实际 ReferencePath、输出程序集及哈希、起止一致性；定义独立验证器及不能关联时的阻断结果。
- **验收场景**：合法混合 TFM 和同名不同版本引用分别绑定；旧 DLL、错误配置／SDK／TFM、缺失生成输入、未知必要输入、依赖冲突、输入变化、失败／取消均不能放行。直接检查薄桥接层不能自行设置 `SourceBound=true`，不能凭时间戳、Git commit 或旧缓存声明本次源码关联。
- **进入下一阶段**：每个支持／拒绝条件有具体输入、预期证据和状态；无法安全重定位时不回退原地构建。

### IP00-D 规则覆盖、门禁与任务状态

- **交付物**：稳定逐规则身份、B 类 xUnit 发现与执行清单、A／B 结果映射；显式规则集合内已启用规则的必检集合及覆盖核对；将规则状态、执行状态、证据等级、限制影响范围、门禁决定和材料状态分别表示的 JSON 契约；CLI `gate`／`status`／`ui` 参数、非零退出码及优先级；每 worktree 锁、共享持久任务、端点身份、取消与重启恢复状态机。
- **验收场景**：pass、violation、inconclusive、error、not-applicable、零发现、全不适用、漏执行、过滤后缺项、partial 可归属／不可归属、构建失败、输入变化和取消逐项判定；同 worktree 重复触发返回现有任务，跨 worktree 独立；关闭页面与取消任务分离，失败／取消不显示旧成功为当前结果。
- **进入下一阶段**：严格判定表和退出码由同一门禁服务产生；severity 不隐式降低必检等级，分析原始状态不被门禁结论改写。

### IP00-E 证据保留、清理与契约验收

- **交付物**：轻量／完整证据目录与索引、完整材料依赖和独立校验契约；最近 30 天且最多 100 次日常运行的选择与排序规则、保护优先级、活动 lease、固定保留、当前门禁与完整证据引用、共享缓存引用；精简历史、整套归档／恢复和 worktree 移除前导出的状态转移表。形成 IP00-A–E 的契约样例、反例、验收矩阵及适用的既有 ArchSift 回归清单。
- **验收场景**：日常成功／违规／失败／取消同样轮转；活动、固定及被引用运行不删，超预算说明原因；缓存仅在无任务和引用时回收；归档迁移后的路径与哈希可重新校验；未知所有权、链接或宽泛目录拒绝清理；轻量摘要不能重新标记为完整证据，已清理历史不能作当前放行。
- **关闭 IP00**：五阶段契约交叉一致，schema、样例、支持矩阵与状态表能覆盖 IP-A01–A13 中归属 IP00 的场景；所有阻碍有明确处置，不虚构已运行的产品验证。

## IP01–IP09 交付与验收场景

下列依赖条件在上表基础上逐包执行。工程 fixture、报告和真实集成材料放在经授权的外置实验目录；真实目标的初始化、忽略规则改动、构建和证据写入需另有具体目标授权。

### IP01 安装与 worktree 宿主

- **交付物**：从明确身份及摘要的本地开发包初始化 `.archsift/` 的配置、规则、版本锁、bootstrap 和独立薄测试项目；只对 runtime／state／reports／evidence 生成所需忽略项；Git 查询定位普通 checkout 与 linked worktree，独立状态、任务锁及载荷摘要核对。此包用于开发验收，IP07 再冻结正式候选及升级、回退、移除的完整生命周期。
- **验收场景**：唯一入口可保存相对路径，多候选要求选择；任意启动目录、`.git` 文件与两 worktree 同提交不同未提交内容均正确隔离；默认离线本地包、摘要不符与显式网络开关、重复初始化和正在运行锁有确定结果；业务 solution／源码无意外改写，自身目录不进入业务发现或快照。
- **完成条件**：合成目标的安装清单、前后文件差异、版本身份和路径／锁负例通过；真实目标操作待 IP08 的具体授权。

### IP02 日常构建与输入关联

- **交付物**：每 run-id 新建输入快照和隔离产物；构建方案预审、实际 solution 配置／项目引用图、明确离线源的恢复与构建、逐项目编译及生成输入取证、实际依赖选择和输出哈希；运行末复核、失败／取消诊断摘要和受控回收。首期不跨次复用业务 DLL。
- **验收场景**：net8/net9/net10、合法混合 TFM／多上下文同名依赖的正例，以及错配置、错引用版本、丢失输入、自定义任务未知输入、失败恢复／构建、过程中源变化与取消的负例；源文件保持原字节、模块初始化器及业务入口未执行，宿主哈希相等。
- **完成条件**：每个受支持项目有实际编译与闭包证据，不能观察的必检范围阻断；关联由验证器核实，桥接层不直接宣称 `SourceBound=true`。

### IP03 xUnit 架构测试与严格门禁

- **交付物**：独立于业务 solution 的薄真实 xUnit 项目、JSON 驱动的 B 类逐规则测试、共享 Worker 桥接和多规则共享程序集模型；A／B 必检清单、覆盖审计、统一门禁服务及完整状态映射。测试发现不触发业务构建，单条测试只供诊断。
- **验收场景**：独立编译合法／违规类型依赖样例产生真实 ArchUnitNET finding；六类规则与既有 ArchSift 的适用语义对照；零测试、全部不适用、过滤／漏执行、违规、无法判定、错误、取消与可归属 partial 的判定正反例；只运行专用架构测试，不执行业务功能测试。
- **完成条件**：逐规则实际发现数与执行数可核对，必检缺口阻断；门禁决定与原分析结果分别保存，双产品适用回归通过。

### IP04 CLI 与日常轻量证据闭环

- **交付物**：显式 `gate`／`status`／`ui` 入口所需的共同任务服务、持久任务与状态查询、轻量关联材料、JSON／HTML／SARIF 结果、新鲜度及 Windows CI 显式接入示例。`--evidence full` 在 IP05 完成前只能返回清楚的未提供状态和非零退出码，不能产出轻量材料却标记为完整。
- **验收场景**：CLI 退出码与严格门禁表一致；重复触发、重启恢复、规则／源码变化、失败／取消后当前结果和历史分离；三格式从同一 JSON 语义投影、HTML 转义、无伪造源码行号；CI 由用户显式调用，无保存或 Git hook 自动运行。
- **完成条件**：轻量等级的真实材料及缺失完整材料的拒绝行为均可检查；完整证据入口由 IP05 激活。

### IP05 完整证据与保留生命周期

- **交付物**：显式 `gate --evidence full` 的项目内或每 worktree 外置完整材料、审查／封存／独立校验；日常 30 天／100 次自动轮转、保护与共享引用、精简历史、完整证据预览／整套归档／恢复和 worktree 移除前导出。
- **验收场景**：轻量与完整同规则得同结果但保证等级不同；成功、违规、失败、取消的轮转与保护冲突；活动任务、固定运行、完整证据／验收／当前门禁引用优先保留，超预算提示；归档后材料可完整校验，恢复后再次核对；越界、链接及未登记目录不清理。
- **完成条件**：完整材料可独立复核，自动回收不会破坏引用，清理后历史索引仍明确材料去向且旧结果不充当前门禁。

### IP06 Web 工作台与双入口一致性

- **交付物**：loopback 单 solution 工作台，目标／worktree 与版本身份、规则编辑、日常／完整入口、任务进度、当前结果与历史／新鲜度、证据和清理预览；CLI／Web 调用同一任务服务与 Contracts。

## 构建和测试执行约束

安装、.NET 构建和真实集成前捕获安全宿主环境／Profile 哈希基线，相关检查点及完成时比较，仅输出摘要和 equality。漂移即停并保留证据，不自动修复。PowerShell 不加载 Profiles；不改 User／Machine 环境、注册表环境或启动脚本；子进程 DOTNET_CLI_HOME 与 DOTNET_ADD_GLOBAL_TOOLS_TO_PATH=0 成对设置。

默认离线恢复、明确来源和参数数组；不忽略恢复失败、不自动安装 SDK／补 PATH。目标自定义 MSBuild 可执行命令，快照不是完整沙箱；按审查过的方案执行。只执行 InProject 控制的专用架构测试，不启动目标应用、模块初始化器、业务功能测试或其他测试入口。无法安全重定位时报告限制，不自动原地构建。

独立编译正反 fixture 按新契约重建。旧 Guard／IFX 数量、缓存存在、旧成功报告或 P05 技术结果不能替代本产品正确性；若选择 Guard 来源资产，先执行 source-inventory 的提交／哈希／权利核对并记录迁移。第三方许可和 attribution 保留。

清理只操作登记的 owned 材料，核对规范绝对路径与包含关系；先停止／等待所属进程，保护活动任务、固定运行和被引用证据。禁止递归删除源根、仓库根或 broad 目录；测试 worktree 使用 Git 正常移除及登记核对。

## 候选验证顺序

1. 执行每工作包有意义的正反检查并记录真实结果；共享改动完成适用双产品回归。
2. 测量代表性输入的复制、恢复、构建、分析、测试和峰值磁盘，分别记录冷／热缓存及环境。冻结参考输入和预算后生成固定候选。
3. 验证候选包、版本／摘要、初始化、升级／回退、门禁及 UI 机器行为、清理与所有权；包括实际 xUnit 执行数，不能把未执行的测试记为通过。
4. 经具体授权后，顺序执行真实 solution 的两 worktree 机器验证；每块检查结果与原件／宿主相等后继续，不用合成成功替代。
5. 独立操作者执行人工清单，记录真实反馈、信心至少 4/5、辅助不高于 L2；实现者不代填。问题修复后重新冻结并复验受影响候选。
6. 明确发布授权后推进正式发布及下载／安装回验，保留失败、未测项和限制，不覆盖已发布资产。
