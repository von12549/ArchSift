# 0.6.0 操作员块 04：独立人工可用性清单

只在 `D:/IFX-10-Root/ArchSift-0.6-review` 的新安装中操作。启动脚本会打开浏览器中的本机启动器；浏览器内私有 URL／token 不要回传或截图公开。脚本将在安全关闭后询问六个 yes/no、总体信心 1–5、最高问题等级和简短备注；请根据实际观察作答，不能观察到的项目答 no 并说明。Agent 不代填人工评分。

1. 在启动器确认当前 0.6.0、选择页等待用户操作而不自行分析。分别观察受管 `config/default.json` 与 config 目录内同名外部 profile 的完整路径、受管配置／规则库标签。外部 profile 不应获得受管配置保护；切换后工作台显示正确 profile 与版本。不要登记 config 外的 profile。
2. 在桌面宽度与约 480px 窄屏查看中文和英文的选择页、工作台、当前任务及历史报告；确认没有遮挡／横向溢出，当前产品版本与旧报告 `toolVersion` 能分辨。
3. 使用现有 `ifx-04-class-A-test`、`real`、existing/net10.0/Debug/offline 的冻结声明规则链查看当前真实 job：准备、执行、报告阶段及条目计数应与本次任务一致；`partial` 与 `compliant` 同时存在时不能被误读为完整源码合规。不要改为 isolated build、联网 restore、程序集规则或运行目标应用。
4. 检查任务取消，以及存在未保存配置编辑时的切换／关闭确认；若任务过短，可诚实记录无法人工观察取消反馈，不为了产生慢任务而修改 IFX 目标或冻结规则。不要保存测试性配置修改。
5. 只在新安装 `config` 下创建或选择一个测试用外部 profile，观察损坏／不兼容 JSON 的逐项错误以及受管默认项仍可选择；不得覆盖受管 `default.json` 或六份冻结策略。若创建了测试文件，记录路径并保留供审核，不自动清理。
6. 在 UI 中安全关闭工作台和启动器，再回到脚本填写人工问卷。关闭浏览器标签不等于停止服务；不要强制终止或留下未保存修改。验收需要 yes/no、信心至少 4/5、最高问题等级不超过 L2，且问题、限制如实记录；脚本只采集回答，最终由 Agent 审核。
