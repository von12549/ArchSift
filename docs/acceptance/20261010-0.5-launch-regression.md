# 0.5.0 CLI UI-launch regression

Date: 2026-10-10 (Australia/Sydney). Development gate only, not final 0.5.0 acceptance.

Running the old implementation's native CLI apphost with redirected stdout/stderr against a synthetic target caused both new tests to time out without startup lines within 15 seconds; the original 142 passed. Evidence: `D:/ArchSift-lab/runs/development-b7d9699d5d544d40a111175ec5f1849b`. SDK 10.0.303/net10.0/Debug/offline locked restore/build succeeded. Host hashes matched throughout and at completion. No real IFX run.

The repair added concurrent output forwarding, 30-second startup detection, a private stdin parent-lifecycle channel, cancellation that first requests shutdown/waits and terminates only the owned process tree after 10 seconds. Web stops on control-pipe EOF; direct Web launch remains independent. Startup tokens reach only operator CLI output; Setup smoke suppresses URLs.

After repair, 107 unit +35 integration +2 architecture =144 passed, zero warnings/errors; evidence `D:/ArchSift-lab/runs/development-62c7133f679e46df8384b6084efd7be9`, equal host hashes. New native-entry tests proved URL/PID/waiting lines, actual HTTP config reads, safe shutdown and Web/PID/listener termination after unexpected parent exit. No analysis report. Cancellation/timeout/error, released self-contained package and human-console acceptance remained future gates.
