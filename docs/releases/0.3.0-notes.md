# ArchSift 0.3.0

ArchSift 0.3.0 adds closed dependency-allow policies and improves large-repository result hierarchy/UI lifecycle.

## Added

- `project-reference-allowlist`: selected projects may directly reference only allowed target projects; supports exact/glob, empty allow sets, scope, exceptions and incomplete coverage.
- `nuget-allowlist`: project-scoped direct PackageReference IDs, case-insensitive; central versions do not change allowance decisions.
- JSON/Markdown templates, schema, CLI/UI, JSON/HTML/SARIF projections and exception attribution for both rules.
- Multiple allowlists intersect; deny remains independent. Overlapping exceptions use a deterministic unique choice independent of file order.

## UI

- Results separate run conclusions, rule conclusions, violation evidence and coverage limits; projects/references form a separate target inventory.
- Large project sets support summary/filter/collapse without hiding limitation count/impact or partial/inconclusive status.
- Each job fixes a target snapshot and continuously shows real/fixture label, root, entry, rules, output, build mode, TFM/configuration.
- Launcher distinguishes session/final-JSON timing, stays attached to its parent and supports auditable safe shutdown.

## Boundaries

- Project allowlist covers resolvable direct references only. NuGet allowlist covers direct declared package IDs, not transitive dependencies/version ranges/online vulnerabilities.
- Incomplete declarations/unbound assemblies retain limitations. Real 105-project IFX results are conservatively partial, not complete source/assembly compliance.
- Windows x64 ZIP is self-contained CLI/Web. Linux CLI has source validation, without Linux Web/self-contained assets.
- Violations do not block by default. No fail-on/required checks/mandatory CI/automatic approved-policy generation.
