# ArchSift 0.3.0

ArchSift 0.3.0 增加封闭依赖允许策略，并改进真实大型仓库的结果层级与 UI 生命周期。

## 新增

- `project-reference-allowlist`：限制所选项目只能直接引用允许的目标项目；支持 exact/glob、空允许集合、scope、exception 和不完整覆盖状态。
- `nuget-allowlist`：按项目范围限制直接 `PackageReference` ID；包 ID 不区分大小写，中央版本不会改变允许判断。
- 两类规则的 JSON/Markdown 模板、schema、CLI/UI、JSON/HTML/SARIF 投影及例外归因。
- 多条 allowlist 取交集，deny 始终独立生效；重叠 exception 使用固定、与文件顺序无关的唯一选择规则。

## UI

- 运行结果分为运行结论、规则结论、违规证据、覆盖边界，项目与引用作为独立目标清单。
- 大范围项目支持摘要、筛选和折叠；limitation 数量、影响和 `partial/inconclusive` 状态不会因折叠而隐藏。
- 每个 job 固定目标快照，持续显示真实/fixture 标签、root、entry、规则、输出、构建模式、TFM 和 configuration。
- 启动器明确 session 与最终 JSON 的产生时机，保持父进程附着，并支持可审计的安全关闭。

## 验证

- Windows / .NET SDK 10.0.303 / Debug：97 unit、31 integration、2 architecture，共 130/130 通过；八模板全部独立 validate/render。
- 真实 IFX 只读 CLI/UI：105 项目、0 程序集、两条预期 allowlist finding；`partial / noncompliant / exit 4`，没有 build、restore 或执行目标应用。
- 独立操作员以帮助等级 L1、confidence 4/5 完成真实 UI 复核；桌面与 480px 窄屏通过。
- 最终宿主、工作树、进程、端口和容器安全审计通过。

## 边界

- 项目 allowlist 只检查可解析直接项目引用；NuGet allowlist 只检查声明模型中的直接包 ID，不覆盖传递依赖、版本范围或在线漏洞。
- 声明不完整或程序集未绑定时继续产生 limitation；真实 IFX 的 105 项目结果是保守的 `partial`，不宣称完整源码/程序集合规。
- Windows x64 ZIP 自包含 CLI/Web。Linux CLI 有源码验证，但不提供 Linux Web UI 或 Linux 自包含资产。
- 违规默认不阻断；本版不启用 fail-on、required checks、强制 CI 或自动生成批准策略。
