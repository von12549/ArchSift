# ArchSift 0.11.0: NuGet project workspace

This release line distributes five matching NuGet packages: Contracts, Core, ArchUnit, Testing and the Cli local tool. Cli includes its matching framework-dependent loopback Workbench, schemas and project template. There is no new installer, self-contained Windows ZIP or standalone Web ZIP. Published 0.10.1 installers and earlier artifacts remain immutable recovery options.

Adopt a single .archsift/start.ps1 entry, shared workspace.json and optional ignored workspace.local.json. Standard .config/dotnet-tools.json, NuGet.Config, global.json and existing architecture policies/tests keep their normal paths. Package initialization creates external user/project state, defaulting to C:/ArchSift-lab, while NuGet owns executable/cache files. Follow the [complete first-use recipe](../../guides/nuget-first-use.md); workspace init consumes existing project configuration and does not scaffold it.

Configured network/private sources and normal NuGet caches are supported with explicit network permission. Offline mode requires an explicit local-only configuration and makes no package/audit request. The public source is https://api.nuget.org/v3/index.json; availability, owners, signatures, downloads and hashes are recorded separately in publication.json. No local candidate or test feed establishes public availability.

Generic project-entry/UI use requires Windows x64, PowerShell 7.4+, stable SDK >=10.0.0 honoring global.json and compatible .NET 10 Core/ASP.NET frameworks. Actual SDK 10.0.100/Core+ASP.NET 10.0.0 is the compatibility-floor fixture; prefer supported current runtime security patches. Linux CLI CI is separate from project-entry/Web qualification. Host discovery reads existing settings; no SDK installation, major roll-forward, persistent PATH/Profile/registry mutation or global tool registration occurs.

Startup does not build or execute the target. Matching Web inventory, state ownership/binding, strict local overrides, concurrent leases, cancellation/dirty-state handling and parent-owned lifecycle remain enforced. Workspace, startup schema-1 and daily-test schema-2 documents are distinct. Use the current invocation's daily-test configuration for inventory and Safe shutdown to end services.

IFX keeps its approved offline source, exact SDK 10.0.303/Core+ASP.NET/host 10.0.13, original architecture/policy paths and 493-case gates. Setup's explicit compatibility list includes stable 0.11.0 only; regexes/schemas and other validation remain unchanged. This release does not broaden future Setup version support or adopt additional IFX rules.

The earlier implemented 0.11.0 package/source passed machine and user acceptance (overall 4/5) before formal registry preparation. That evidence remains historical and does not automatically accept rebuilt final packages. The exact final source, regression/audit/consumption/lifecycle evidence and new user-only acceptance are bound in acceptance.json; NR00–NR04 preparation does not tag, upload or publish. Repository signing may change archive hashes without changing payload; final manifests distinguish qualified submissions and verified served packages.

Preserve complete prior package/manifest/locks/config/state/entry combinations before upgrading. Rollback retains later edits, reports and new state/evidence; no automatic historical managed fallback, shared-cache purge or PATH repair. Published ID/version bytes are never overwritten; unlisting does not revoke exact-version restores. Product MIT and all included third-party license/notice texts remain unchanged.
