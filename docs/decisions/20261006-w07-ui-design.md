# W07 local-workbench design

Date: 2026-10-06 (Australia/Sydney).

Use frontend-design guidance for a local architecture workbench aimed at .NET developers: select scope, understand declaration graphs, review rules and distinguish violations from inconclusive results.

Blueprint-blue colors rather than marketing gradients: background#eef3f6, ink#1e3c50, interaction#276a8c, pass#147264, inconclusive#94632e, violation#a24140. Heading Bahnschrift/Microsoft YaHei; body Microsoft YaHei; paths/JSON Consolas. System fonts only, without external resource loading.

Layout:
```text
Brand / current-run status
Target, artifacts, rule paths    Project relationships and scope
Ruleset forms / exceptions      Results, coverage, inconclusive items
Historical runs                 Report and draft-rule exports
```

Remove generic statistics cards/marketing hero after reviewing the brief. Center actual target roots/current state/project relationships. Configuration/rule editing have explicit boundaries. Failed current runs cannot retain successful results; old records are separate history. Use left alignment, compact hierarchy, visible focus, single-column narrow layout and no default looping animation. Interaction labels are Discover projects, Verify rules, Save rules and Cancel this run, without requiring users to understand Worker/proof lifecycle internals.
