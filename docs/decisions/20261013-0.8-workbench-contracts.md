# 0.8-1A History, aggregate and evidence-entry contracts

2026-10-13, user-authorized 0.8.0 stage 1. Initial plan commit d07fba9 was pushed. This freezes implementation contracts, not completed UI/evidence jobs.

History defaults to current output.directory. Additional directories explicitly register target identity; registration index is `.archsift-history.json` in the current report root. Lost/corrupt indices can be re-registered and actual reports rescanned; the index is not conclusion authority. Read only nonlinked files inside registered roots with bounded file reads and streaming traversal. Validate report v1, chain-summary v1/v2 and comparison v1 against formal schemas; retain unavailable diagnostics for corrupt/unsupported records. Valid old records lacking runMetadata/time expose remaining facts with unknown markers; absent execution/details never manufacture conclusions. Scanning executes no target entry point and writes no old files.

Main records use canonical material path plus runId; actual hashes diagnose content changes. Copies in different directories retain provenance and are not merged solely by runId. Link live/saved results by current artifact path/runId. Chain roots associate child reports, which are not separate main records; missing/corrupt children appear in detail diagnostics. History viewing neither changes config nor implicitly validates. Freshness is not-revalidated; explicit current validation gets its own task record. Pagination offset>=0, limit 1–100. Sort real offset-bearing started times in UTC, unknown times last, with stable material-identity ordering; no mtime.

ChainAggregate is a Core runtime projection from actual entryId/ruleId details; no new persisted aggregate field or existing report/chain schema change. Web responses include aggregate; CLI writes a separate readable stderr summary; HTML/History use the same function. Five rule-status counts must sum to RecordedRules; findings count separately. Duplicate entries or duplicate ruleId within an entry are material errors; identical ruleIds across entries count separately. Missing/skipped/failed/cancelled never count as completed. ReportedEntries counts actual details, EndedEntries terminal states, CompletedEntries only execution=completed, partial separate. Use shared unique summary project count, not child-coverage sums. Without owner/context identity, show only saved context statistics or unknown, never infer complete coverage. SourceBound requires all planned entries/reports and coverage.sourceBound=true throughout; do not rewrite exit/compliance/partial.

Use saved startedUtc (including existing offsets) and elapsedMilliseconds; missing old fields are null. UI shows full date/time with explicit user-zone offset and preserves original time in details. New jobs persist actual created/started/finished times and Stopwatch duration. Failures/cancellations get separate task records; viewing time is not execution time.

Core EvidenceStoragePlan accepts explicit DataRoot or EvidenceRoot and stable project/run IDs, default `<DataRoot>/evidence/<projectId>/<runId>/assembly-manifest-v3.json`. Apply S1–S5 safe path segments, create-new, outside-source/protected-directory/reparse checks and upgrade retention. Core never reads installation Profiles. Stage 1 only calculates/displays directories or reads existing materials; no external build.

Evidence-detail GET and explicit POST evidence validate use the current job's frozen config and existing discovery/Existing verification chain. Clients cannot supply SourceBound/exits. Propagate cancellation; failures do not reuse old validation. Existing run gate prevents config-edit races. Implement `/api/evidence` and `/api/history` while preserving `/api/jobs` live operations. History registration writes and evidence POST retain session token/Origin/path boundaries. No new network/execution authority or human review approval.
