# 0.8-1A History、汇总与证据入口契约

2026-10-13，用户授权的 0.8.0 第一阶段。首条计划提交为 d07fba9，已推送；本决议冻结实现契约，不代表界面或证据任务已完成。

History 目录默认当前 output.directory，额外目录显式登记目标身份，目录登记索引置于当前报告根的 `.archsift-history.json`；索引可损坏/丢失后重新登记并扫描实际报告，不将索引当结论权威。只读取登记根内非链接文件，有界逐文件读取，目录流式遍历；report v1、chain-summary v1/v2、comparison v1 按正式 schema 校验，不支持版本/损坏项保留 unavailable 诊断。合法旧记录缺 runMetadata/时间时读取其余字段并标未知，缺执行/明细仍不可制造结论。扫描不执行目标入口，不写旧文件。

主记录按材料规范路径＋runId 标识，实际文件哈希用于内容变化诊断；同 run 在不同目录保持来源身份，不能只按 runId 错合并不同字节。live 与已保存结果用本次 artifact 路径/runId 关联。Chain 根目录关联子报告，子报告不列独立主记录；缺失/损坏 child 在详情诊断。历史查看不改变配置，不隐式 validate；freshness 固定 not-revalidated，显式当前验证另有任务记录。分页 offset>=0、limit 1–100，真实带偏移 started 时间转换为 UTC 排序，缺时间排后且使用材料身份作稳定次序，mtime 不参与。

ChainAggregate 是 Core 从真实 entryId/ruleId 明细生成的运行投影，不新增持久 aggregate 字段，不修改既有 report/chain JSON schema。Web 结果响应带 aggregate，CLI 输出独立可读摘要到 stderr，HTML 使用同一投影；History 使用同一函数。五类规则计数求和必须等于 RecordedRules，finding 独立计数。重复条目/同条目重复 ruleId 属材料错误，跨条目同 ruleId 分别计数；missing/skipped/failed/cancelled 不能被算成 completed。ReportedEntries 表示实际报告明细，EndedEntries 表示终态，CompletedEntries 仅 execution=completed，partial 单列。项目数用 summary 的共享唯一项目数量，不累加子覆盖；owner/context 无身份可核对时只显示已保存上下文统计或未知，不推断完整覆盖。SourceBound 只有计划条目全部存在、报告存在且 coverage.sourceBound 都为 true 才成立，退出/合规/partial 不改写。

时间使用保存的 startedUtc（包括已有带偏移表示）与 elapsedMilliseconds，旧缺字段为 null。UI 以用户时区显示完整日期/时间和明确偏移，详情保留原时间。新 job 保存 created/started/finished 的真实时间与 Stopwatch 耗时；失败和取消落独立任务记录，不使用查看时间充当执行时间。

证据目录由 Core EvidenceStoragePlan 接收明确 DataRoot 或 EvidenceRoot 与稳定项目/运行 ID，默认 `<DataRoot>/evidence/<projectId>/<runId>/assembly-manifest-v3.json`；标识安全路径段、create-new、根外/受保护目录/重解析校验及升级保留规则按计划 S1–S5。Core 不读取安装 Profile。第一阶段只计算/显示目录或读取既有材料，不执行外置构建。

证据详情 GET 与显式 POST evidence validate 使用当前 job 冻结 config，调用现有 discovery/Existing 验证链；不允许客户端提供 SourceBound/退出码。取消贯穿 token，失败不沿用旧验证；任务按现有运行 gate 防止与配置编辑竞争。Web 路由在实现阶段接 `/api/evidence`、`/api/history`，保留 `/api/jobs` 的既有 live 操作。History 写登记与 evidence POST 继续会话 token/Origin/路径边界。无新的网络/执行权，不产生人工 review approval。
