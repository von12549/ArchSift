# ArchSift 0.5.0 Setup contracts

Date: 2026-10-10 (Australia/Sydney). **FROZEN FOR IMPLEMENTATION** under 0.5.0 execution authorization. Setup is a separate self-contained Windows x64 console program without PATH dotnet dependency. Machine JSON is English; documentation was Chinese at this historical stage.

## Commands

The syntax below belongs to 0.5.0, not 0.4.0. Reject duplicate options and unknown fields/arguments.

```text
ArchSift.Setup.exe --version
ArchSift.Setup.exe inspect --root <install-root>
ArchSift.Setup.exe acquire --version <version> --sha256 <expected-zip-hash> --output <new-zip>
ArchSift.Setup.exe plan install --root <root> --package <zip> --sha256 <hash> --target <root> --entry <relative-sln/csproj> --tfm <net8.0|net9.0|net10.0> [--configuration Debug|Release] [--output <reports>] [--library <rules>] [--smoke true|false]
ArchSift.Setup.exe plan adopt --root <root> --version-directory <existing-payload> --config <existing-config>
ArchSift.Setup.exe plan upgrade --root <root> --package <zip> --sha256 <hash> [--smoke true|false]
ArchSift.Setup.exe apply --plan <reviewed-plan-json> --plan-id <displayed-sha256>
ArchSift.Setup.exe rollback --root <root> --receipt <successful-receipt-id> --selection-sha256 <current-install-json-hash>
ArchSift.Setup.exe recover --root <root> --operation <interrupted-operation-id> --journal-sha256 <reviewed-journal-hash>
```

plan/inspect write no disk files; operator may save complete stdout plan JSON. Plan ID is canonical JSON SHA-256 excluding planId value, valid 24 hours. Apply requires same ID and rechecks package/config/library/selection hashes, safe paths/existing versions; any drift rejects. Verified same-package upgrade is no-op; same version/different bytes rejects.

acquire is the only network operation: explicit version/ZIP hash, fixed von12549/ArchSift GitHub Release archsift-<version>-win-x64.zip, new-file write without execution. Hash proves integrity, not independent publisher signature. User must review version acceptance/publication. No online restore, SDK installation, PATH/environment repair.

## Identity and compatibility

Setup JSON schemaVersion=1. install.json records roots/target/config/library/selection, managed paths/manifest hashes and last operation. Plan records operation/expiry/package/generated new-install config/preselection/state hashes/smoke request. Receipt records before/after selection/state hashes/backup/result. Journal records transaction/plan/selections and prepared/backed-up/staged/configured/committed/completed/aborted. Ownership covers explicit payload/Setup state/new config only, never automatic old-version/user-data deletion.

Original package-manifest schemaVersion=1, win-x64, selfContained=true, clean fixed source. Verify every payload length/SHA-256; reject missing/extra/duplicate/case-collision/traversal/absolute/link/reserved-name entries. ZIP <=1 GiB, total extraction <=2 GiB, file <=256 MiB, <=10,000 entries. Atomically move verified staging to same-volume versions/<version>.

Known 0.4.0 config/library/chain schemaVersion=1 may be adopted; 0.5.x requires setup-compatibility.json declaring the same schemas. Unknown families/schemas/migrations reject. Supports compatible byte-preserving upgrades, **no schema migration**. Preserve old binaries/rules/entryIds/tombstones/dangling chains/references/order. No rule imports/target analysis/policy creation during upgrade.

## Transactions and recovery

Apply takes exclusive .archsift-setup.lock, rejects active old-version processes/unfinished transactions. After service stops, back up config/full library including registry/tombstones/chains with matching before/after hashes; reverify managed versions. Reports retain paths rather than being copied for switches. Upgrade changes only install.json selection, not state bytes. Optional precommit private UI smoke loads config/safe-shuts down without URL/token in logs/receipts. Lazy library initialization may add internal empty registry/lock only; existing bytes cannot change.

Journal intent precedes each write stage. Final selection is commit point; receipt reconstructs from journal. After interruption, operator reviews journal hash: current=after completes receipt; current=before marks aborted and retains exact staging/backup/version/config for review; other states reject. No broad cleanup. Same-version retry reuses only completely hash-verified retained directories.

Rollback selects only successful upgrade before-state, requiring current selection equal receipt after and state hashes unchanged. Later user edits reject/preserve. Compatible upgrade needs no state restoration; unknown migrations reject. No uninstall/automatic version cleanup in this release.

## Safety and acceptance

Install/target roots cannot overlap in either direction. Config/output/library avoid links/reparse/target paths and versions/operations/install.json conflicts; no UNC/remote roots. Initial install never overwrites unknown files/existing config. Every mutation captures/compares same-process User/Machine environment, Process PATH and Windows PowerShell/PowerShell 7 Profiles, prints only hash/equality, stops/preserves journal on drift without repair.

Exits: 0 success/verified no-op; 2 config/compatibility/conflict; 3 execution/verification failure; 130 cancelled. Actual regressions cover concurrency/stale plans/corrupt-hostile ZIP/no SDK/UI stdout-stderr-timeout-cancel-parent exit/bytes/upgrade-rollback/interruption at every stage. Real IFX remains one operator-reviewed command block at a time.
