# ArchSift 0.5.0 setup 契约

日期：2026-10-10（Australia/Sydney）。状态：**FROZEN FOR IMPLEMENTATION**。范围由 0.5.0 执行授权确定。setup 为独立自包含 Windows x64 控制台程序；不会依赖 PATH 上的 dotnet。机器输出为英文 JSON；说明文档使用中文。

## 命令

下列语法属于 0.5.0；0.4.0 不提供这些命令。命令选项不可重复，未知字段/参数拒绝。

```text
ArchSift.Setup.exe --version
ArchSift.Setup.exe inspect --root <install-root>
ArchSift.Setup.exe acquire --version <version> --sha256 <expected-zip-hash> --output <new-zip>
ArchSift.Setup.exe plan install --root <root> --package <zip> --sha256 <hash> --target <root> --entry <relative-sln/csproj> --tfm <net8.0|net9.0|net10.0> [--configuration Debug|Release] [--output <reports>] [--library <rules>] [--smoke true|false]
ArchSift.Setup.exe plan adopt --root <root> --version-directory <existing-payload> --config <existing-config>
ArchSift.Setup.exe plan upgrade --root <root> --package <zip> --sha256 <hash> [--smoke true|false]
ArchSift.Setup.exe apply --plan <reviewed-plan-json> --plan-id <displayed-sha256>
ArchSift.Setup.exe rollback --root <root> --receipt <successful-receipt-id> --selection-sha256 <current-install-json-hash>
ArchSift.Setup.exe recover --root <root> --operation <interrupted-operation-id> --journal-sha256 <reviewed-journal-hash>
```

`plan`/`inspect` 不写入磁盘；stdout 的完整 plan JSON 可由操作者保存。Plan ID 为去掉 planId 值后的规范 JSON SHA-256，有效期 24 小时。Apply 必须传相同 ID，再核对原包/配置/库/选择文件哈希、目标安全路径和已有版本；任何漂移拒绝。重复相同包升级是经过核验的 no-op；同版本不同字节拒绝。

`acquire` 是唯一联网操作，固定下载 `von12549/ArchSift` GitHub Release 的 `archsift-<version>-win-x64.zip`，显式版本和 ZIP 哈希，写新文件；不执行下载内容。哈希是完整性证据，不是独立发布者签名。用户仍须审阅该版本 acceptance/publication。没有在线 restore、SDK 安装、PATH 或环境修复。

## 身份与兼容性

setup JSON schemaVersion=1。`install.json` 保存根、目标、配置/库、已选版本、所有受管版本的路径和 manifest 哈希、最后操作身份。`plan` 保存操作、过期时间、包身份、生成配置（仅新安装）、前置选择/状态哈希和 smoke 请求。`receipt` 保存前后选择、状态哈希、备份目录和操作结果。`journal` 保存同一事务、计划、前/后选择和 `prepared/backed-up/staged/configured/committed/completed/aborted` 阶段。所有权只覆盖明确 manifest payload、setup 状态和新建配置；不自动删除旧版本或用户数据。

原始 package-manifest schemaVersion=1、win-x64、selfContained=true、干净固定源码；验证每个 payload 的长度与 SHA-256，拒绝缺项、多项、重复/case collision、ZIP traversal、绝对路径、链接及 Windows 保留名。ZIP 上限 1 GiB，展开总量 2 GiB、单文件 256 MiB、10,000 项。只将校验完整暂存目录原子移动到同卷 `versions/<version>`。

0.4.0 已知 config/library/chain schemaVersion=1 可接管；0.5.x 必须有 `setup-compatibility.json` 声明同样的三个 schemaVersion=1。未知版本族/未知 schema/迁移一律拒绝；本版支持兼容字节保持升级，**不提供 schema 迁移**。保留旧二进制、规则 bytes/entryId/墓碑、悬空 chain 与全部引用/顺序。升级不导入规则、不分析目标、不创建策略。

## 事务和恢复

Apply 使用根下独占 `.archsift-setup.lock`；拒绝活跃旧版本进程和未完成事务。配置和完整 library（包括 registry/tombstone/chain）在服务停止后生成前后双哈希一致备份，受管版本再次核验。Reports 保留，不为切换版本而复制。升级不改状态字节，只切换 `install.json`；可选 UI smoke 在提交前加载配置并私有请求安全关闭，URL/token 不写 receipt/log，库 lazy initialization 仅允许新增内部空 registry/lock，原有字节不可变化。

Journal 在每个写阶段之前记录意图。最终选择文件是提交点，receipt 从同一 journal 可重建。中断后 `recover` 要求操作者审阅 journal 哈希：当前选择等于 after 就补完 receipt；等于 before 就标记 aborted 并保留精确记录的 staging/backup/version/config 供检查；其他状态拒绝。恢复不宽泛删除文件。后续同版本重试只复用哈希验证完整的保留目录。

Rollback 仅回选成功 upgrade 的 before，验证当前选择和 receipt after 完全相等、状态与升级后哈希相同；有后续用户编辑时拒绝并保留。兼容升级无需恢复状态；未知迁移拒绝。本版不提供卸载或自动旧版本清理。

## 安全与验收

Root/目标双向不重叠，配置/输出/库不跨 links/reparse、不在目标内，用户状态不与 versions/operations/install.json 冲突；不支持 UNC/远程根。首次安装未知文件/已有 config 拒绝覆盖。每次变更捕获并比较同一进程 User/Machine 环境、Process PATH、Windows PowerShell/PowerShell 7 Profile 文件身份，只打印 hash/equality，漂移停止且保留 journal；不得自动修复。

Exit：0 成功/经核验 no-op；2 配置/兼容/冲突；3 执行/校验失败；130 取消。并发、stale plan、损坏/恶意 ZIP、无 SDK、UI stdout/stderr/超时/取消/父退出、字节身份、升级/回退及每阶段中断均需真实回归；真实 IFX 必须操作者一次一块已审查命令。
