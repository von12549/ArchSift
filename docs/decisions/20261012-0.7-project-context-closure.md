## Scope and evidence

Add assembly-manifest v3 and external-build-review v2. Keep capture v1 and strict single-closure validation for manifest v1/v2. Each discovered first-party project has exactly one analysis owner context. Actual DLL, SDK/TFM/Configuration, source identity, external snapshot and successful build evidence remain fully bound.

Each context has a stable ID, owner sourceProject, unique primary assembly, explicit resolved reference paths and evaluation material path. Actual MSBuild `ResolveReferences`/`getProperty`/`getItem:ReferencePath` output binds MSBuildProjectFullPath, TargetPath, AssemblyName, TFM/Configuration and all selected references. Validator reads actual selections without guessing from directory scans, filenames or highest versions. First-party references must match current project DLL identities from the same build. Capture external references before build; bind generated inputs through actual materials.

Keep build snapshot outside source root. Relative paths/byte identities of captured source in the snapshot must match; snapshot evaluation is not a second unverified source root. Changed material/snapshot/environment/SDK/assemblies revoke binding. Never execute analyzed application, module initializer or test entry points.

v3 reference directories explicitly model project compilation resolution for standard .NET 8/9/10 semantics. Each simple assembly name selects one concrete PE identity per context; different contexts may select different versions. Check requested name/culture/public-key token individually. Equal versions resolve; bound actual selections at least as new as requests may resolve under explicit `dotnet-reference-path` policy. Do not generalize this to arbitrary AssemblyLoadContext callbacks, runtime plugin probing, replacements, API compatibility or full application executability; these stay excluded.

Version rule follows [Microsoft AssemblyLoadContext documentation](https://learn.microsoft.com/en-us/dotnet/core/dependency-loading/understanding-assemblyloadcontext): one version per simple name per context, loaded version at least the requested version. ArchSift additionally requires hash-bound actual selection evidence and strict culture/token; absent evidence rejects. Framework references use actual selected, precaptured reference surfaces, never analyzer-host fallback.

SDK reference-surface endpoints must be inside the actual SDK dotnet/packs Microsoft.NETCore.App.Ref/Microsoft.AspNetCore.App.Ref net8/9/10 ref directories, have PE ReferenceAssemblyAttribute (including a MethodDefinition reference in that assembly) or be method-free, forwarder-only SDK facades, and be precaptured/actually selected. These are compile API contracts; unused optional forwarders are not runtime closure and do not require every optional implementation package. Verify all static references in first/third-party implementations; framework references still check selected name/version/culture/token. An arbitrary external DLL with a same-named attribute cannot impersonate the SDK boundary. [Microsoft reference assembly documentation](https://learn.microsoft.com/en-us/dotnet/standard/assembly/reference-assemblies) supports this distinction.
