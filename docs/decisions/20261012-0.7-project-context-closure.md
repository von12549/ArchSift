# 0.7.0 项目／加载上下文分区闭包

2026-10-12。用户明确将此项纳入 0.7，要求完成真实 IFX 源码绑定、逐阶段提交／推送；最终独立人工 UI 仍由用户完成。之前单一闭包的拒绝和失败材料保留，不能改为通过。

## 范围与证据

新增 assembly-manifest v3 与 external-build-review v2；capture v1 保留，旧 manifest v1／v2 的精确单闭包校验不放宽。每个已发现第一方项目必须有且仅有一个分析所属上下文，实际 DLL、SDK／TFM／Configuration、源码身份、外置构建快照及成功构建证据仍完整绑定。

每个上下文包含稳定 ID、所属 sourceProject、唯一 primary assembly、明确的已解析 reference paths 和求值材料路径。求值材料是实际 MSBuild `ResolveReferences`／`getProperty`／`getItem:ReferencePath` 输出，绑定 MSBuildProjectFullPath、TargetPath、AssemblyName、TFM／Configuration 与全部选中引用。验证器读取该材料核对具体选择，不能根据扫描目录、文件名或最高版本猜测依赖。第一方引用必须与同一次构建中对应项目的当前 DLL 身份一致，外部引用须在构建前捕获；生成输入另按实际材料绑定。

构建快照位于源根外，捕获源码在快照中的相对路径／字节身份须一致；快照求值不能被当作另一个未核验源码根。材料、快照、环境、SDK 或程序集改变撤销 source binding。所分析程序入口、模块初始化器和测试入口均不执行。

v3 的引用目录明确属于项目编译解析上下文，支持 .NET 8／9／10 标准解析语义。上下文内每个简单程序集名称只允许一个已选择的具体 PE 身份；不同上下文可以选择不同版本。逐个请求核对 name、culture、public-key token；版本相同可解析，已绑定实际选择且版本不低于请求时可按显式 `dotnet-reference-path` 策略解析。不得将它泛化为任意自定义 AssemblyLoadContext 回调、运行时插件探测、程序集替换、API 兼容认证或完整应用可执行性证明。这些仍在范围外。

版本规则依据 [Microsoft AssemblyLoadContext 文档](https://learn.microsoft.com/en-us/dotnet/core/dependency-loading/understanding-assemblyloadcontext)：一个上下文每个简单名只容纳一个版本，已加载版本必须不低于请求。ArchSift 还要求实际选择的哈希绑定求值证据及严格 culture／token；没有该证据仍拒绝。框架引用也使用本上下文实际选中并预捕获的 reference surface，不能靠分析器宿主补足。

SDK 框架 reference surface 的终点必须位于实际 SDK 所属 dotnet/packs 的 Microsoft.NETCore.App.Ref／Microsoft.AspNetCore.App.Ref、对应 net8／9／10 ref 目录，并具有 PE ReferenceAssemblyAttribute（包括属性引用本程序集 MethodDefinition 的形式）或仅含转发项、没有方法的 SDK facade，且已预捕获、实际被项目选中。它是编译 API 契约，未使用的可选类型转发项不构成程序运行时闭包；不能因此要求所有可选实现包存在。第一方／第三方实现程序集的全部静态引用仍核验，引用到框架时也须核对已选择契约的名称／版本／culture／token；任意带同名属性的外部 DLL 不能冒充 SDK 边界。[Microsoft reference assembly 说明](https://learn.microsoft.com/en-us/dotnet/standard/assembly/reference-assemblies)支持此编译契约区别。

## 分析与报告

实际 `ReferenceCopyLocalPaths` 可补充只在实现闭包中出现的依赖，必须与同一项目求值材料一致；不能把 ReferencePath 未列出的实现依赖直接当作不存在。copy-local 的具体实现可替代非 SDK 编译引用，但其 name／culture／token 与版本须兼容，且文件预捕获或有本次生成证据。卫星资源及 native/data 资产仍绑定哈希；它们不是普通托管代码源，不合并进中性程序集名字表，也不作 native 执行／动态资源加载的认证。第一方及第三方静态托管依赖不因此免检；直接声明引用不兼容仍拒绝。

Core 校验并构造上下文，CLI／Web 使用相同 Core 和 Worker 契约。Worker 对每个上下文用独立、禁用缓存的 ArchUnitNET 架构，仅将所属第一方程序集作为规则源；依赖定义用于解析，不能作为另一个项目的源码重复计数。框架／第三方类型可以是依赖目标。元数据工作目录只包含该上下文的已选择字节，不按其他上下文或宿主进行回退；按精确记录的 owned 目录清理。

结果按规则聚合：matched 为唯一所属第一方源实体数量；未匹配其他项目不造成假 inconclusive，整体零匹配仍 inconclusive／not-applicable。任一实际违规保留 violation；缺少或失效的上下文不能获得当前源码 pass。finding 身份和 location 包含稳定上下文身份，避免同名类型跨项目碰撞；JSON／HTML／SARIF 和 chain 身份保留上下文证据，排序不改变结果。

report 可选 buildContext 字段区分 project-contexts 与旧单闭包并记录 context count；assemblyCount 表示唯一分析所属第一方程序集数，依赖副本不重复计数。声明层未求值条件仍显示原 scope 限制，所以可信 B 类型结果可能 sourceBound=true、逐条 pass／violation，但整体 execution 仍 partial／exit 4；不能以此改变 A 类声明规则结论。

v3 review／manifest 使用单独有界 JSON 大小（最多 16 MiB），读取前检查文件长度；旧规则、capture、v1／v2 清单的 4 MiB 限制不变。增加此界限是为了容纳 105 项目的显式引用与材料，不能静默省略证明。Worker 请求同样有界。

## 阶段与门禁

静态托管闭包从该上下文的 primary owner 出发，递归核验每个可达第一方／第三方实现程序集的全部静态 AssemblyRef；不能仅核对 owner 一层。未被任何可达代码引用的设计工具／部署资产依然绑定选择与哈希，但不当作应用代码的必需闭包。这不认证动态加载或完整程序运行时。SDK reference 契约仍为边界；可达依赖中缺文件、降级或被指定 token 不符均拒绝。

P2 实际取证补充：便携编译的 copy-local 表包含未限定 RID 的资产及多个平台候选。当前支持便携编译上下文，以未限定 RID 的实际资产补实现闭包，其他 RID 候选与资源／native 资产保留哈希，不猜测宿主或最高版本，不认证任意部署 RID 行为。请求若携带非空 token，仍要求精确相符；若请求没有 token，不能把空 token 误认为一个被指定的强名称身份，可按已证明的具体 .NET 选择绑定已命名 DLL。旧 v2 的 token 精确规则不变；v3 实际选中 DLL 的完整 PE 身份和哈希仍核对，错强名称／降级／culture 不符继续拒绝。[Microsoft .NET 5+ strong-name 绑定说明](https://learn.microsoft.com/en-us/dotnet/standard/assembly/strong-named)支持无 token 请求与具体已命名资产的区别；不作签名认证。
