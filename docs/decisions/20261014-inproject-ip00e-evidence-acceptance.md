# ArchSift.InProject IP00-E：证据保留、清理与契约验收

日期：2026-10-14（Australia/Sydney）。依据：[产品规格](20261014-archsift-inproject-0.1.0-product-spec.md)、[IP00-B 路径契约](20261014-inproject-ip00b-config-paths.md)、[IP00-C 构建关联](20261014-inproject-ip00c-build-binding.md)、[IP00-D 门禁与任务](20261014-inproject-ip00d-gate-jobs.md)和[实施计划](../plans/20261014-archsift-inproject-0.1.0-implementation-plan.md)。本记录完成 IP00 的设计契约验收；产品运行验收仍在 IP01–IP09。

## 两级材料与身份

每个 worktree 的运行使用唯一 run-id，`reports/<run-id>/` 保存权威 JSON 报告、HTML／SARIF 投影、轻量关联材料和状态索引；默认完整材料位于 `evidence/<run-id>/`，可由本 worktree 本机设置指向经归属校验的外置专属根。轻量材料须包括业务／规则／工具摘要、构建上下文、IP00-C 实际编译与引用捕获摘要、独立关联验证决定、逐规则测试清单、门禁判定和必要日志。构建临时快照可在确认无活动任务或引用后回收；轻量摘要不能因此被声明可独立重放。

完整材料须额外保留结论所依赖的原始输入快照、生成输入、程序集／依赖闭包、构建与测试原始记录、审查、封存和独立校验清单。归档必须是整套目录加 manifest，不仅是报告 PDF／HTML。manifest 绑定产品／工具／规则版本、worktree、run-id、相对路径、字节长度和 SHA-256；链接、重解析点、绝对路径、重复路径与大小写碰撞拒绝封存／恢复。迁移后重算哈希并运行独立校验，路径基准变更以 manifest 的逻辑相对路径处理，不把旧绝对路径误判为现时输入身份。`daily` 不得修改标签成为 `full`；缺少任何完整依赖材料时 full 验证失败而原始日常结论仍按历史保存。

运行状态与材料状态分开：门禁可以 `allow`／`block`，材料可以 `available`／`compacted`／`archived`／`missing`，新鲜度可以 `current`／`stale`。清理后保留精简历史索引，记录原门禁、原输入／规则／工具身份、原等级、清理时间、材料去向和引用；旧通过不可充当前门禁。失败、违规、取消也有独立 run-id 与轻量诊断，纳入同一轮转队列，不用成功覆盖它们。

## 自动保留与引用保护

默认 `retentionDays=30` 且 `maxDailyRuns=100`。以终结时间、run-id 稳定排序；`now - finishedUtc > 30 days` 为超期，未来时间戳视为异常不自动删除。对**未受保护的日常运行**先清超期，再从最旧开始清到剩余数量不超过 100。两条件均要满足；保护优先于上限，故可能超预算并明确报告数量／空间与原因。只按登记 manifest 中整套 owned run 目录清理；不得递归删除 worktree 根、`.archsift/` 根、`reports/` 根或外置证据根。

保护集合由以下引用的传递闭包构成：活动／排队任务及 lease，用户固定运行，当前门禁，完整证据／验收记录，归档预览或正在迁移的运行，以及共享缓存被任一活动任务或保留材料引用。引用存储 run-id、引用者与类型；未知引用者或索引损坏按保护处理。完整证据默认不进入日常自动轮转，仅在用户明确选中具体 run-id 并查看预览后执行整套归档或删除。未受保护的缓存须在相关进程完全退出且引用计数为零后回收。清理前重读 lease、引用和目录身份；期间发生变化即放弃该项。目录 owner 标记、规范绝对路径、真实路径、包含关系、无链接及 manifest 哈希都要核对；未知所有权、另一 worktree、受保护目录一律不清理。

| 操作 | 前置条件 | 结果与失败语义 |
| --- | --- | --- |
| 自动轮转日常材料 | 终态、未受保护、精确 owner、无活动 lease；预览名单重新核对 | 原子更新精简索引后回收登记目录；删除失败保留 `available`／诊断，不虚报已清理 |
| 精简历史 | 日常材料已安全回收 | 保留原结论和身份，`materials=compacted`，当前门禁另行重算 |
| 全量归档 | 明确选中 full run，预览完整依赖与目标位置，独立验证通过 | 写新归档、重验哈希后标记 `archived`；失败保留原材料 |
| 归档恢复 | 校验归档 manifest、每个文件、路径归属和目标 owner | 恢复到新的 owned 目录并再验证；不可修改旧结论或绕过新鲜度 |
| full 删除 | 明确选中、预览、没有活动／固定／验收／当前门禁引用 | 删除整套登记材料并保留历史索引；有引用则拒绝 |
| worktree 移除前导出 | 展示本地 reports／evidence／state 中需保留的项 | 经用户明确选择导出并验证；Git worktree 移除仍按 Git 流程，外置证据单独保留 |

容量阈值在 IP07 实测并冻结，不凭空宣称固定预算。超预算时不能为了满足数量而删除受保护材料。归档与恢复的具体命令／状态在 IP05 实现，IP00-E 仅冻结不可丢失的语义。
