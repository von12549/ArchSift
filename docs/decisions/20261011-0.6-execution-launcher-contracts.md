# 0.6-A 执行与启动器契约

日期：2026-10-11（Australia/Sydney）。状态：FROZEN FOR IMPLEMENTATION。用户已授权全部 0.6.0 计划实施、每阶段提交／推送及后续 PR、合并、文档更新、发布；真实 IFX 和人工可用性仍为操作员门禁。

## 可执行契约与版本

Contracts 的 `ChainRunOptions.MaxConcurrency` 默认 1，schema 拒绝 1–4 外整数、非整数、字符串、重复 key 和未知字段。CLI 为 `--max-concurrency`，Web 为 chain 请求的 `maxConcurrency`；policy/config schema 不改。B 阶段先只执行串行，参数真正的 2–4 调度由 E 实现，不在中间候选声称已支持并行。

`chain-summary.schema.json` 保留 v1 原字节；新 `chain-summary-v2.schema.json` 独立约束 schemaVersion 2，在 snapshot 中强制 `executionOptions`。新的 ChainSummary 由 B 生成 v2；已有 v1 可反序列化并按 v1 校验，不给其虚构并发／计时。进度是独立 schemaVersion 1 快照，不将临时进度混入最终 findings。C 增加 v2 可选 timings：`preparation/evidence/evaluation/inputVerification/reportWriting/total` 毫秒；evaluation 的端到端区段可能包含子分析中的复核，计时明确允许重叠，不相加当总耗时。

Core 同步发出 `ChainProgress`，由宿主绑定 jobId 并原子保留最新快照。runId 从准备之前生成，revision 单调递增；每次发布复制条目数组。endedCount 是所有终态数；executedCount 仅 completed/partial（包括 noncompliant），skippedCount 仅 skipped，runningCount 是 running/writing。失败／取消另外通过条目状态可见，不计为成功执行。outputAvailable 仅表示本次完整子报告或诊断已落盘，不表示策略通过。终结 job 必须晚于最终 summary 成功写出。

阶段、条目状态和取消／漂移语义见正式计划第 3 节。冻结字节之后的规则库编辑不改当前政策；source/build 漂移则撤销受影响绑定。Job gate 必须先取得，再创建任务和准备，避免忙碌时仍扫描新目标。提交时保存 chain 定义与已保存 ruleset 字节，准备 job 内发现源；准备取消没有 source 时产生 skipped 审计，不冒充零项目成功。

## 启动器宿主边界

启动器由 Web 宿主运行独立 loopback 引导页并拥有一个工作台 Web 子进程；CLI `launch --root` 是其外层生命周期父进程。Web 启动器复用 Setup 的只读包／安装安全核验；Setup 保持不依赖 Web，Core 不引用 profile／Setup。可用新 Web→Setup 引用共享核验，无新包依赖；架构方向检查要明确允许此宿主引用。

元数据为 `config/profiles.json` 和 `config/selection.json`，独立 schemaVersion 1；新受管文件 `config/default.json`。Catalog 每安装最多 100 项、每 JSON 最大 4 MiB；路径和 profileId 唯一，default 必须引用登记项。configProtected/libraryProtected 是读取安装状态之后的 SessionProfile／列表投影，禁止持久化自称保护。不同路径相同名字／字节不合并。

引导页与工作台均使用 loopback/origin/session-token 防护、CSP 和正文上限。引导页 API：GET state，POST register（name/configPath/预期清单 hash）、POST create（name/configPath/config/预期清单 hash）、POST start（profileId）、POST stop、POST shutdown。所有 mutation 校验字段和 hash；未完成退出拒绝新 start。登记／创建须显示完整路径及 JSON 审阅；外部原 JSON 只读，create 仅 configRoot 内空闲非元数据路径。无元数据且唯一受管配置路径有效时，明确呈现初始化清单预览，再由用户确认登记，不在 GET 或 smoke 隐式写入。

D 实施细化：只读 POST preview 将新 JSON 的相对路径按目标配置文件目录解析，完整展示后才 create；start 额外核对 catalog/config/selection hash。未知 selection schema 在启动时也拒绝覆盖。工作台回报未保存区段；启动器关闭按钮明确审阅将放弃的会话修改，活动 job 始终拒绝关闭。私有 profile 消息使用紧凑单行 JSON＋stdin-v1 生命周期，不将多行格式化 JSON 当单行协议。两类宿主固定 Production 和随包 wwwroot，避免开发态静态资产映射成为包外依赖。

开始前校验安装身份和 profile bytes，使用显式参数数组启动选中版本 Web；URL/token 通过内存回调传递，不写日志或元数据。API 响应中的工作台地址限私有会话，不持久保存。新工作台接收 SessionProfile，通过匿名私有 stdin 启动消息传入，之后仍由 stdin EOF/shutdown 控制父生命周期；环境只传通道标识，不传 JSON/token。显式 ui --config 的可见 URL 行保持不变。

切换前用户在旧工作台处理任务及未保存编辑；启动器查询私有会话 readiness/shutdown。未保存 UI 表单的判断由旧工作台呈现，不能仅凭“无活动 job”自动放弃。旧服务完整退出后才启动新会话。父退出及取消需要 drain 当前 audit，超时只终止精确拥有的进程树。

## 安装与验收

Setup schemaVersion 1 和旧 receipt 不改；新安装路径改 default.json，config 外 legacy 升级拒绝且不迁移。兼容包族是明确 0.4.0/0.5.x/0.6.x，同 config/library/chain schema 1；未知族／schema 拒绝。安装完整性核验与配置健康分离，使缺失 JSON 不阻止引导页显示。profiles/selection 保留原字节但不纳入单 ConfigPath 的 receipt 状态；不得用对整个 config 目录备份冒充多 profile 保护。

回归矩阵由正式计划 V/P/L/S/M/H 项约束。A 的 schema/DTO 测试核对参数上下界、重复／未知字段、元数据资源上限与禁止 token／保护字段；B 验证状态时序及取消，D 验证真实 owned 子进程、路径冲突和元数据并发写入，E 验证实际有界调度与串并行语义，F 验证精确原生包和操作员现场。中间阶段不发布未完成候选。
