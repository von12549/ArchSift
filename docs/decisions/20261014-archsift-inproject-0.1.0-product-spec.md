# ArchSift.InProject 0.1.0 产品规格

日期：2026-10-14（Australia/Sydney）。状态：**PRODUCT BASELINE CONFIRMED / IMPLEMENTATION NOT STARTED / NOT ACCEPTED / NOT RELEASED**。

用户在本次需求讨论中逐项采纳下列产品决议及首期验收基线。ArchSift.InProject 是共享 ArchSift 核心、面向单个 solution 和 worktree 的独立产品宿主。现有 ArchSift 继续作为独立目标分析产品。实施工作包见[实施计划](../plans/20261014-archsift-inproject-0.1.0-implementation-plan.md)。

## 产品关系与支持范围

两个产品在当前 ArchSift Git 仓库开发，共享 Core、Contracts、规则语义、ArchUnitNET Worker、报告和证据校验能力，分别打包、验收和发布。共享修改需要双产品适用回归；Core 不依赖 CLI、Web、InProject 宿主、worktree 管理或 xUnit。

| 项目 | 首期范围 |
| --- | --- |
| 宿主 | Windows x64 CLI 和 loopback Web UI；工具沿用 .NET 10 平台，构建和测试还需匹配的目标 SDK 与测试运行时 |
| 目标 | SDK-style C#，单个 `.sln` 或 `.slnx` 入口，net8/net9/net10 |
| 构建维度 | 明确选择 Configuration 与 TFM，按项目记录实际上下文；多 TFM 分次检查，默认 Debug |
| 项目范围 | 清点 solution 成员、未列入项目、外部／未解析引用和不支持项目；必检范围及其项目引用闭包须明确覆盖 |
| worktree | 普通 checkout 和 Git linked worktree；配置随分支携带，本地任务和材料相互隔离 |
| 规则 | 复用现有六类规则、已支持模板、例外与组合语义；JSON 为规则权威 |
| 门禁 | 临时快照构建、本次输入关联核验、真实 xUnit 架构测试、严格必检 |
| 入口 | 显式 CLI／Web 触发；Windows CI 接入示例；Agent 使用相同 CLI 语义 |
| 报告 | JSON／HTML／SARIF，中文可读 UI；区分规则结果、执行状态、证据等级和门禁决定 |
| 管理 | 规则编辑、历史、新鲜度、证据保留与清理、锁定版本安装及显式升级／回退 |

规则范围内的静态编译后依赖结论不扩张为运行时、动态加载、部署或完整应用可执行性认证。现有规则表达能力的缺口继续列明；真实测试入口本身不补齐方法调用精度或类型归属规则。

## 项目内安装与版本控制

目标仓库根目录使用 `.archsift/`。布局中的文件名是设计约定，具体 schema 和包内部布局在契约阶段冻结。

```text
目标仓库/
├─ Product.sln
└─ .archsift/
   ├─ project.json         # 跟踪：相对入口、项目与门禁配置
   ├─ rules/              # 跟踪：规则、例外与理由
   ├─ version.lock.json   # 跟踪：工具版本和载荷摘要
   ├─ bootstrap/          # 跟踪：初始化与启动脚本
   ├─ tests/              # 跟踪：专用架构测试项目、源码和依赖锁
   ├─ runtime/            # 忽略：预编译载荷
   ├─ state/              # 忽略：本 worktree 状态、锁和临时构建
   ├─ reports/            # 忽略：本地报告
   └─ evidence/           # 忽略：本地证据
```

配置路径相对于配置文件解析。初始化发现唯一候选可默认选中；多个候选须明确选择并保存相对入口。新 worktree 依据已提交版本锁初始化自己的载荷与状态，默认使用明确指定的本地包，联网获取须显式启用。

Git 忽略只覆盖本地产物目录，不能忽略整套配置。业务发现、规则匹配和快照复制排除工具运行目录；工具配置、规则、测试桥接与版本身份另行绑定。业务编译若引用被排除的工具文件，应报告范围冲突，不能静默隐藏。Git worktree 定位使用 Git 查询，兼容 `.git` 文件，不能假定它为目录。

## 证据等级与存储

完整证据默认位于 `.archsift/evidence/<run-id>/`，本地报告位于 `.archsift/reports/`；允许每个 worktree 显式指定外置证据根，本机绝对路径保存在本地设置中。每次运行使用唯一目录，成功、失败和取消均有独立终态，不覆盖旧结果。

| 等级 | 使用场景 | 保留内容与保证 |
| --- | --- | --- |
| 日常轻量证据，默认 | 频繁开发门禁 | 输入／规则／工具摘要、构建上下文、编译与程序集关联记录、结果及必要日志；不默认长期保存完整快照和依赖材料 |
| 完整验收证据，显式选择 | 阶段验收、发布检查、长期复核 | 完整输入快照、程序集与依赖材料、构建记录、审查及校验材料、报告，保留结论实际依赖的文件 |

两个等级使用相同规则语义，报告明确不同可复核保证。日常摘要不能通过改标签升级为完整证据；历史摘要可能需要重新构建才能复核。其他 worktree 的材料不能直接作为当前门禁依据，必须重新核验。

InProject 拥有的可写目录与业务输入范围须通过新的显式路径契约隔离，不能整体关闭现有路径保护。现有 ArchSift 的源根外证据策略保持。项目内嵌套快照必须防止递归复制、意外祖先 MSBuild 导入及工具文件进入业务编译。快照不称为 OS 安全沙箱。

## 证据保留与清理

日常轻量证据默认保留最近 **30 天**、最多 **100 次运行**，可由项目配置调整。对未受保护的超期或超数量运行优先清理最旧记录；成功、违规、失败和取消采用相同规则。完整验收证据持续保留，仅在用户明确选择后整套归档或删除。

正在运行或占用、用户固定保留，以及被完整证据、验收记录或当前门禁结果引用的运行，不参与自动清理。保护优先于数量和容量预算；超出时提示占用与原因。容量默认提示阈值在实测后冻结。

可重建缓存／临时材料仅在无任务使用、无证据引用后回收。清理按完整运行核对所有权、规范绝对路径、包含关系、链接与引用；共享材料必须解除全部引用才可回收。完整证据先展示具体预览；归档包含材料与索引并校验完整性，恢复后重新校验。

清理保留精简历史索引，记录原结果、运行身份、清理时间及去向；材料标为已清理／已归档，历史通过不能作为当前门禁通过。移除 worktree 前提供保留清单与导出入口；直接删除 worktree 会丢失其中本地证据，外置证据独立保留。

## B 类规则与真实架构测试

采用薄架构测试项目、JSON 驱动和共享 Worker。首期只支持 xUnit，其他框架适配暂缓。每条启用的 B 类规则对应可识别测试用例，输出规则 ID、实际 finding 或无法判定原因。生成源码负责测试入口、数据和显示名称，规则判断仍由共享实现执行。

专用测试项目位于 `.archsift/tests/`，首期不加入业务 solution，由 InProject 门禁入口运行。直接运行单条测试可用于诊断，不能跳过完整门禁的构建关联与覆盖核对。测试发现不应触发业务构建或执行其他目标测试。

桥接层传递已核验上下文并映射结果；Core／Worker 不依赖 xUnit。测试项目 TFM、测试运行器、xUnit 版本以及与 .NET 10 Worker 的调用边界在契约阶段冻结，不能迫使 net8/net9 业务项目升级。分析采用元数据路径，不执行业务应用入口、模块初始化器或业务功能测试。

## 日常构建与本次输入关联

每次运行在 `.archsift/state/build/<run-id>/` 新建临时输入快照、隔离产物和执行记录。业务源码保持只读，首期不复用以前的业务 DLL，也不以普通 `bin/obj`、文件时间或 Git commit 作为关联证明。允许使用明确来源且经过核验的 SDK 文件和离线包缓存。

一次门禁完成以下步骤：

1. 冻结当前业务输入（包括相关未提交修改）、规则、工具、SDK 和构建设置身份。
2. 捕获并核验输入副本；快照排除工具产物，目标明确依赖的生成输入须另行捕获。
3. 按 solution 配置和实际引用图构建，核对必检项目覆盖；恢复默认离线，恢复成功后禁止隐式恢复。构建方案须审查，自定义 tasks／generators 的未知输入不能被忽略。
4. 记录实际编译输入、参数、imports、生成器／任务及成功状态，绑定输出程序集身份与哈希。
5. 按项目核验实际 ReferencePath、TFM／Configuration 和依赖闭包，支持不同上下文的不同版本选择。
6. 运行专用架构测试，多个规则共享构建结果与对应程序集模型，不逐规则重新构建。
7. 复核当前业务输入、规则和程序集未变化，核对全部必检规则执行情况，保存轻量关联记录与报告。
8. 进程退出、无引用后按清理策略回收临时材料，失败／取消保留诊断摘要与必要日志。

日常关联需要新契约，不允许桥接层直接设置现有 `SourceBound=true`。无法观察必要编译过程、核验输入／依赖或安全重定位时，保留限制并阻断相关必检规则；不能自动回退到业务源目录构建。输入变化撤销本次关联。完整验收仍走完整材料的审查、封存和独立校验流程。

## 严格必检与入口

门禁只运行显式选定的规则集合，其中已启用规则默认全部必检。首期 severity 仅用于展示和排序，不自动降为观察规则。

| 结果 | 门禁判定 |
| --- | --- |
| 全部必检通过，输入关联与覆盖成立 | 放行 |
| 必检 violation／inconclusive／error | 阻断，JSON 保留不同类别 |
| 构建失败、取消、输入变化、漏执行 | 阻断 |
| not-applicable | 仅规则显式允许为空且覆盖成立时接受 |
| 零测试发现或全部必检不适用 | 不放行，未形成有效检查 |

保留分析原始 partial 等执行状态；只有限制明确不影响必检范围、其余条件成立时才可放行。影响无法归属时阻断。分析结果、执行状态、保证等级与门禁决定分别记录，不能重写分析报告使其看似完整。

CLI、Web、Agent 和 CI 使用同一门禁服务。显式触发自动完成一次完整流程；文件保存、commit／push 不自动触发，相关输入变化使旧结果失效。同 worktree 默认只运行一个门禁任务，重复触发展示已有任务，不同 worktree 独立运行。CLI／Web 相互查询任务，关闭页面与取消任务分开。

CLI 拟定 `gate`、`gate --evidence full`、`status` 和 `ui` 入口；最终参数／退出码在契约阶段冻结，放行返回 0，其余终态非零并区分原因。Web 首页展示 worktree／目标、规则集合、构建配置、证据等级、进度与结果。运行开始标为运行中，失败／取消不展示旧成功为当前结果。

## 版本与发布

两个产品独立版本和标签。ArchSift 延续 `v…` 序列，InProject 从 `0.1.0` 开始，标签采用 `inproject/v0.1.0` 形式。共享组件和测试桥接首期随产品固定分发，不另设公开发布流程。

每个包固定产品名／版本、Git 提交、共享组件身份、契约版本及载荷摘要。项目锁定具体版本与摘要，不追随 latest；显式升级／回退保留配置、规则、证据和历史，工具变化使受影响旧门禁失效。不能自动降级或重写配置，也不能覆盖已发布包字节。

Patch 用于兼容修复；Minor 用于新增能力，0.x 的破坏性变化须明确迁移说明；进入 1.x 后破坏性契约变更提升 Major。候选使用 alpha／beta／rc 标识。发布依次冻结源码、构建候选、产品验收、正式发布及下载／安装回验；共享变化执行双产品回归，但不要求同步发布。

## 验收基线

验收以实际行为与材料为准，不预设测试数量。每项均须记录 SDK／TFM／Configuration、输入与候选身份、覆盖及限制。

| ID | 标准 |
| --- | --- |
| IP-A01 | 任意启动目录定位、候选歧义拒绝、锁定版本初始化、自身排除及规则／工具身份绑定准确。 |
| IP-A02 | 普通 checkout／linked worktree、同提交不同未提交修改、并发任务／端点／材料隔离成立。 |
| IP-A03 | 同输入规则的双产品逐规则语义一致；规则、例外或工具变化使旧结果失效。 |
| IP-A04 | xUnit 真实发现并逐规则执行；独立真实编译合法／违规样例得到预期结果和 finding。 |
| IP-A05 | 旧 DLL、输入变化、错 SDK／TFM／配置、生成输入缺失、构建失败、产物篡改均不能放行。 |
| IP-A06 | 合法跨 TFM 引用、不同上下文同名不同版本能正确处理；缺失、冲突或错误选择不通过。 |
| IP-A07 | pass／violation／inconclusive／error／not-applicable、取消、零发现、全不适用、漏执行及限制影响归属按严格策略处理。 |
| IP-A08 | CLI／Web 共用任务结果，重复触发、重启恢复及关闭／取消语义准确；无旧成功残留。 |
| IP-A09 | 两等级保证准确；完整材料可独立校验；嵌套快照不递归复制或意外继承构建输入。 |
| IP-A10 | 30 天／100 次轮转、保护优先、引用回收、整套归档／恢复及清理索引正确。 |
| IP-A11 | 安装／升级／回退／移除载荷保留数据，身份／摘要不符拒绝；worktree 移除前能导出保留材料。 |
| IP-A12 | 除授权 `.archsift/` 和忽略规则变更外，业务源码、solution 和构建配置不改写；宿主无持久漂移，取消／清理／越界安全检查通过。 |
| IP-A13 | 共享修改后的现有 ArchSift 适用回归通过，外置证据和只读目标策略保持。 |
| IP-A14 | 用户明确授权的一个真实 solution、两个 worktree 完成机器验证；独立人工验证初始化、门禁、结果理解、恢复、规则与证据管理，信心至少 4/5、辅助不高于 L2。 |
| IP-A15 | 实测复制／恢复／构建／分析／测试及峰值磁盘，冷／热分别报告；先冻结参考输入和预算，再验证固定候选及发布资产。 |

既有 ArchSift／IFX 通过记录仅为历史与回归参考，不能替代新产品当前验收。真实目标执行需新的具体授权；独立人工答案由操作者填写。

## 延期范围
