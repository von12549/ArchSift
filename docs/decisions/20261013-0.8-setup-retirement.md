# 0.8 Setup version-removal and uninstall contracts

The user explicitly selected S4 supplementary scope on 2026-10-13: reviewed version-removal/uninstall commands, rebuilt candidate and machine acceptance. This does not authorize changing the original IFX 0.7 installation or replace independent human UI acceptance.

`plan remove-version` permits only registered versions that are **not currently selected**; `plan uninstall` handles all registered versions and `install.json`. Both require an operator-selected, nonexistent same-volume archive directory and a JSON array listing every custom evidence root (`[]` if none). Default `<install-root>/evidence`, configured report directories and config files are included automatically in read-only checks. The plan records selection, config/library, evidence file-set hashes and exact version identities. Apply within 24 hours with `apply-retirement --plan ... --plan-id ...`; reject expiry, changes, running owned processes, links, escaped paths, archive collisions and unfinished Setup operations.

Execution atomically moves only version directories verified against package manifest and complete file lists into same-volume `versions/<version>` archives; never recursively delete the install root. Uninstall also archives original `install.json` and writes `uninstalled.json` as a recovery pointer. Config, rule library, reports, default/custom evidence, failed/cancelled attempts, project registrations, History index and receipts retain paths/bytes. Archives preserve product bytes and provide recoverable cleanup without promising disk-space recovery. Known evidence/config/report references to version paths block retirement. References may hide in unlisted roots/private binary formats, so the operator must review the root list. Do not mark broken archived absolute references currently validated.

Persist `operations/<id>/retirement-journal.json` before moving. If interrupted while original selection remains, `recover-retirement` uses the reviewed journal hash to return exact archived versions and record `aborted`. If new/uninstalled selection is already persisted, verify archived/retained materials and complete the receipt. Recovery rejects selection/state/evidence drift. Normal install/upgrade/rollback also rejects unrecovered retirement journals. Actual space recovery needs a separate explicitly reviewed archive-cleanup design; recoverable retirement does not authorize irreversible deletion.
