# 0.8 Setup 版本移除与卸载契约

S4 补验范围由用户在 2026-10-13 明确选择：0.8 增加受审查的版本移除及卸载命令，重打候选包和机器验收。此决议不授权修改原 IFX 0.7 安装，也不代替独立人工 UI 验收。

`plan remove-version` 只允许移除已登记且**非当前选中**的版本；`plan uninstall` 处理所有已登记版本和 `install.json`。两者均要求由操作员指定同卷、尚不存在的归档目录，并提供 JSON 数组文件列出全部自定义证据根（无自定义根时为 `[]`）。默认 `<安装根>/evidence`、配置指向的报告目录和配置文件自动列入只读检查。计划记录选择、配置/规则库、证据文件集合的哈希和精确版本身份，24 小时内以 `apply-retirement --plan ... --plan-id ...` 执行；复核时拒绝过期、改动、正在运行的所属进程、链接、越界路径、归档碰撞、未完成的其他 Setup 操作。

执行仅把经过 package manifest 和完整文件列表核验的版本目录原子移到同卷归档 `versions/<版本>`，不递归删除安装根；卸载还把原 `install.json` 移入归档并在原根写 `uninstalled.json` 恢复指针。配置、规则库、报告、默认/自定义证据、失败/取消尝试、项目登记、History 索引和操作回执保持原路径原字节。归档保留原始产品字节，属于可恢复的软清理，不承诺释放相同磁盘容量。已知证据/配置/报告中的版本路径引用阻止操作；路径引用可能藏在未列出的自定义根或非文本私有格式中，因此操作员必须审查根清单。不会把归档后失效的绝对引用标记为当前已验证。

`operations/<id>/retirement-journal.json` 先于移动落盘；应用中断时，原选择尚在则 `recover-retirement` 依据审查过的日志哈希将精确归档版本移回并记 `aborted`，新选择/卸载选择已经落盘则核验归档与保留材料后完成回执。恢复拒绝选择、状态或证据漂移。普通安装/升级/回退也拒绝未恢复的 retirement journal。归档后若需要实际释放空间，应另起显式归档清理设计与审查，不能把此软清理当成不可逆删除授权。
