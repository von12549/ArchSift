# 0.7.0 外部证据与 UI 契约

2026-10-12（Australia/Sydney）。0.7-1 设计冻结；实现与验收分别记录，不以设计替代运行证据。

## 外部构建证据

保留 assembly-manifest v1 与 isolated 路径；新增 v2 的 `reviewedBuild` 字段。来源标记固定为 `external-reviewed`，不宣称 ArchSift 自行重建。报告的 buildContext 保留既有 binding 枚举，新增可选 evidenceOrigin 与 evidenceSha256；身份纳入 manifest、审查记录、日志和外部输入哈希。

CLI `evidence capture --config --output` 在构建前生成 source capture（由 Core 计算 InputIdentity 与 BuildInputIdentity）和未批准的审查模板。外部构建必须在源根外的快照进行，由操作员先审查命令、离线 restore 来源、自定义构建风险和输出路径。CLI `evidence seal --config --capture --review --output` 在构建后核对当前输入、审查材料、DLL 字节和元数据，生成清单；不运行构建或应用。`evidence validate --config` 复用与 analyze/verify 相同的 Core 验证器。

审查记录必须指向构建前 capture；包含 SDK、TFM、Configuration、实际命令数组、成功退出码、构建日志、构建求值／输入跟踪证据和审查说明（均有字节哈希）、每个项目的已求值程序集／TFM、所有实际读取的构建输入及其内容身份、条件使用的环境值哈希、显式全局属性、生成器／自定义任务／导入清单与剩余未知项。模板默认未批准且含待解决项；只有操作员确认输入跟踪完整、构建成功且未知项为空后才可 seal。评审确认是外部信任边界，SHA-256 只证明内容身份，不证明审查真实性。

工具直接复核当前源码输入、文件／环境哈希、项目覆盖、上下文一致、DLL SHA-256／PE 名称和配置、依赖闭包的版本／culture／token。工具不运行 MSBuild 求值；已求值属性及跟踪完整性由操作员依据哈希绑定的实际构建日志／求值记录审查。只解除有完整外部证据的程序集绑定限制；声明层的条件项目／包规则继续保持保守语义。所有发现项目都必须映射，缺项不绑定；未追踪外部输入、审查缺页、生成器／任务未知、构建失败、源或 props 变化、SDK／TFM／配置不一致、DLL／闭包不符均不可 pass。零类型匹配仍 inconclusive。

capture 的 `--inputs` JSON 显式列出全部外部输入路径（含实际 SDK 工具与所用框架程序集）；源码声明中的属性表达式名称自动加入环境哈希集。构建后新增的输入必须重新 capture／build，禁止 seal 时才补录身份。review 的项目求值属性必须覆盖声明引用的全部属性名，记录显式全局属性；框架程序集以单独 frameworkPaths 指向已捕获输入，逐项 PE 身份核对，不靠分析器宿主的同名 DLL 自动免检。trace、log、review-notes 分别作为哈希绑定的材料；后续 verify 再次复核所有可变外部输入，材料变更撤销绑定。

0.7-3 复核补充：SDK／导入／任务的额外环境键通过可选 `--environment-inputs` 名称数组一并捕获。框架 reference surface 按完整 PE 身份匹配，允许实际 SDK 同时使用 netstandard／net8／net10 的不同框架版本，不允许同名新版本替代旧引用；非框架同名冲突仍拒绝。没有第一方项目／程序集的清单不能声明当前源码绑定。

0.7-4 定向复核：IFX 实际使用 `MSBuildProjectName.EndsWith(...)` 实例属性函数；捕获其基底属性名并要求每个项目提交已求值事实，条件函数的真假仍由 trace 审查。SDK／restore 的派生输入通过 generated-input 材料绑定，缺失该材料拒绝。完整有效证据持续复核所有输入；已明确拒绝的审查不重复扫描整个 SDK。

外部文件在验证时仍须可读取和哈希复核，清单及材料放在源根外。seal 用 create-new 防止旧清单被覆盖。捕获前后相同源码并不自行证明 DLL 由它编译；该因果关系属于审查记录的外部证明，产品与文档必须明确。IFX 输入若不能完整取证，就列出具体限制，保持 inconclusive。

## Create From

Ruleset 复制读取 library.Export 的已保存字节，创建无 entryId 的草稿；填写新的 ruleset ID 与文件名后调用创建专用 API `/api/library/create/{filename}`。服务端在库锁下执行大小写不敏感 ID／文件冲突检查、create-new 文件发布和 registry 回滚，保留现有更新 API。

Chain 复制读取已保存 chain，保留有序 entryId；新草稿可编辑 ID，原对象编辑仍锁定 ID。新建通过 `/api/chains/create/{id}`，在独立文件锁下校验并以无覆盖发布。缺失引用显示原 entryId，保存前必须修复，禁止按文件名重新绑定。编辑前使用既有未保存保护，取消不变更草稿；复制不运行分析。

## Rule results 排序

每个结果表持有独立排序状态，三态循环为升序、降序、默认。Rule 用完整可见 ID 按 ordinal 比较；Result 升序固定为 violation → error → inconclusive → pass → not-applicable，降序反向。同状态用 rule ID 升序、原行号稳定打破平局。渲染使用数组副本，不修改报告；切换 job／子报告重置。表头按钮支持键盘与 aria-sort，状态序有可见双语说明。

## Launcher 关闭

确认 → closing（锁定竞争控件）→ accepted → 轮询认证 session 端点。正常 HTTP 响应说明端点仍可达；拒绝请求恢复按钮并显示错误；接受后连续失联只能显示“服务端点已不可达；可关闭此页，进程退出未由浏览器确认”，不能以 HTTP 200 或网络错误证明进程退出。超时显示仍可达并允许重试。会话保护保留：活动 job 拒绝，工作台须先安全关闭。sessionStorage 保存关闭终态，刷新时重新探测，旧终态不得覆盖当前可达服务。CLI exit、owned 进程与监听退出由包／人工验收分别核对。

## 验证门禁

外部证据正例必须实际编译条件／表达式合成项目并由真实 ArchUnitNET 检查 pass／violation；不是伪造 SourceBound 的内存测试。反例覆盖所有上述拒绝情形和旧 manifest 回归。复制覆盖并发／双击、大小写、路径冲突、缺失引用和失败一致性，UI 包含 406 行与窄屏。真实 IFX 与原安装升级不得以合成门禁代替；每次执行前保留宿主哈希与输入身份。
