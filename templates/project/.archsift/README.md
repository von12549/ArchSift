# Project Workbench entry

Adopt these files under the target project's `.archsift/` directory, choose a unique stable `project.id`, and pin ArchSift.Cli in the existing root `.config/dotnet-tools.json`. In the NuGet package the entry is stored as `start.ps1.template`; copy it to the project as `start.ps1`. This template is never an automatic NuGet install script. Preserve other tools. Keep standard NuGet.Config/global.json and existing policy/test files at their original locations. A local tool is not a PackageReference that executes a UI during a project build.

The project entry requires PowerShell 7.4 or later. From the project root, run `pwsh -NoProfile -File ./.archsift/start.ps1`. The default is Launcher. Use `-Mode Workbench` for direct Web, `-Action Init` for preparation without UI and `-Action Doctor` for diagnostics without tool restore/state migration. An absolute script path works from another directory. `-NoBrowser` controls explicit headless Launcher operation. Use `-InteractiveRestore` only when a standard NuGet credential provider requires an explicit sign-in; it streams instructions without persisting authentication output and has a bounded wait. Doctor never prompts or restores.

`workspace.json` is the versioned workspace contract, not a schema-1 analysis/startup JSON or a schema-2 daily-test JSON. Relative paths resolve beside it, `project.root=..` selects the project root, and `project.entry` is project-root relative. Optional `workspace.local.json` uses kind `archsift-workspace-local`, schemaVersion 1, and can override only state.root, runtime.dotnetPath, nuget.cacheDirectory and nuget.configFile. Add `/.archsift/workspace.local.json` to the project ignore file. Do not commit local paths or secrets.

Configured mode explicitly permits the sources selected by standard NuGet configuration. Offline mode requires allowNetwork=false and an explicit local-only standard NuGet.Config. Exact versions remain in the root tool manifest; missing packages do not trigger source/version substitution. The entry honors normal cache settings unless explicitly overridden. It never clears shared caches or modifies User/Machine NuGet settings, environment, PATH, registry or PowerShell Profiles. Child CLI homes disable global-tool PATH registration.

The installed stable SDK must be >=10.0.0 (actual SDK feature-band versions start with values such as 10.0.100), satisfy project global.json, and provide compatible .NET 10 Core/ASP.NET shared frameworks. Configure runtime.dotnetPath or use existing host environment/PATH discovery. Startup never installs an SDK, edits global.json or enables cross-major runtime roll-forward. IFX retains its exact independent host/source/policy approvals.

State defaults to C:/ArchSift-lab and is partitioned by user/project. Choose another writable external root in configuration when needed. Initialization creates owned configuration/library/report/session directories, without target builds or application execution. Package/cache/runtime files and generated startup/daily configs/logs/reports stay outside the repository. Unknown/busy/mismatched state is preserved, not repaired or overwritten. Back up editable libraries, local settings and state independently; NuGet cache cleanup must not remove them.

Keep previous package/manifest/approval/config/state/entry backups when upgrading. Use an explicitly reviewed, hash-bound `-Migration` manifest for library/inactive-history import. Do not import old reports as current success. Rollback restores the complete recorded combination after checking destination drift; preserve later `.archsift/` files and never recursively delete that directory.
